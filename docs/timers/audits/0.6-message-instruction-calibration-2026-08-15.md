# 0.6 Watchdog message-instruction calibration

Date: 2026-08-15

Status: partial evidence; exact full-message instruction totals are unavailable
from the pinned PocketIC 15 public test surface

## Question

How much of a complete timer-generated IC message is represented by the
instruction aggregates retained by `ic-timers` for a minimal Watchdog and a
bounded representative Watchdog callback?

The requested comparison is total PocketIC message instructions, retained
scheduler instructions, retained work instructions, and the unaccounted
difference. Values that the evidence boundary cannot observe must remain
unavailable rather than being derived from cycles.

## Subjects

Both subjects link the exact released `ic-timers` 0.6.0 runtime into the
optimized `testing/size-probe` Watchdog canister and run in a fresh PocketIC
instance:

- `minimal` increments one bounded callback counter and returns
  `NoWork / Continue`;
- `representative` performs 100,000 deterministic integer-mixing steps and
  returns `Success(1) / Continue`.

The second body is a dependency-free, bounded synchronous calibration load.
It is not IcyDB database logic and does not claim to model an IcyDB page or a
production instruction budget.

Each Watchdog cadence uses two timer-generated messages. The scheduler message
commits the successor and queues work; the later work message runs the
consumer callback. The retained role aggregates begin immediately before
`ic-timers` callback acceptance and close after completion processing and any
successor binding. They exclude the start/end page reads, the later bounded
summary write, provider execution before entering `ic-timers`, and provider
return/reply work after it returns.

## Result

Two consecutive runs on the same optimized artifacts produced identical
calibration rows:

| Watchdog profile | Total PocketIC message instructions | `ic-timers` scheduler instructions | `ic-timers` work instructions | Unaccounted difference |
| --- | ---: | ---: | ---: | ---: |
| Minimal | Unavailable | 20,944 | 18,275 | Unavailable |
| Bounded representative | Unavailable | 20,976 | 1,918,290 | Unavailable |

PocketIC 15 exposes the canister cycle-balance delta for the two-message
cadence, but its public Rust client and subnet metrics do not expose the exact
per-update instruction total needed for the first column. Consequently the
residual cannot be calculated. The observed cycle values are retained only as
a separate regression signal:

| Watchdog profile | Two-message cycle-balance delta |
| --- | ---: |
| Minimal | 30,730,996 |
| Bounded representative | 32,626,842 |

Cycles are not converted to instructions: the balance delta includes message
and platform charges and is not an instruction counter. Instrumenting or
patching the provider would also change the subject, so this audit does not
present such a build as exact release evidence.

## Consequences

- The instruction aggregate is useful bounded runtime telemetry, but it is not
  proof that the complete IC message remains below its instruction limit.
- The 0.5 and 0.6 numbers must not be compared without labeling their stated
  measurement boundaries.
- Hard safety claims continue to require real message-level trap or
  instruction-exhaustion evidence. IcyDB's 40-billion-instruction probe is the
  relevant downstream class of evidence.
- A future exact table requires a PocketIC or replica evidence surface that
  reports total instructions for each uninstrumented timer-generated message.
  Until then, the unavailable cells are an explicit open evidence boundary.

## Reproduction

```text
make pocketic-cohorts
```

The run used Rust 1.88 and `pocket-ic-server 15.0.0` with SHA-256
`29472ea4433b30a280676c4e22e369d79d5ba6ee1b4d48bab32ebe7d0ad2b4bb`.
The calibration additions are confined to the repository's test canisters and
do not change the published crate, runtime API, or provider protocol.
