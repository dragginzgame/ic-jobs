# 0.5 memory-sampling instruction probe

Date: 2026-08-15

## Question

What call-context instruction overhead do the start/end Wasm and stable-memory
page reads add around an otherwise empty normally completed Watchdog scheduler
or work interval?

The answer must remain separate from `TimerPerformance` instruction
aggregates. Those aggregates deliberately begin after the start page read and
end before the final page read, preserving their pre-0.5 interval.

## Method

The existing `testing/size-probe` Watchdog cohort registers one retained
one-second Watchdog whose synchronous work only increments a bounded callback
counter and returns `NoWork / Continue`. Its scheduler contains no consumer
work.

A probe-only update method measures two instruction-counter brackets in the
same IC message:

1. an empty bracket containing two inert tuple barriers; and
2. a sampled bracket containing the exact two extent reads used for callback
   start and end.

Each extent read executes Wasm `memory.size` and IC `stable64_size`. The tuple
results pass through `std::hint::black_box` so the optimizing build cannot
discard them. Subtracting the empty bracket removes the common
`performance_counter(1)` boundary cost. Wasm disassembly confirms that the
sampled path retains both `memory.size` instructions and both stable-size
calls.

This benchmark endpoint exists only in the size-probe canister. It does not
change `ic-timers`, its public API, its production snapshots, or the callback
instruction interval.

## Result

PocketIC 15.0.0 reported the following deterministic values in two consecutive
runs of the Rust 1.88 optimized Watchdog cohort:

| Subject | Call-context instructions |
| --- | ---: |
| Empty counter bracket | 200 |
| Start/end page-read bracket | 200 |
| Observed page-read overhead | 0 |
| Empty Watchdog scheduler aggregate | 20,947 |
| Empty Watchdog work aggregate | 18,425 |

The measured added call-context instruction charge for the four page reads is
therefore zero in this PocketIC subject. The same page-read operations surround
both normally completed scheduler and work intervals, so the result applies to
each role. It does not mean that the complete messages execute zero
instructions; the table reports only the delta attributable to those page
reads.

The end-to-end Watchdog dispatch used 30,732,302 cycles in the same run. That
balance delta includes both provider messages and all runtime work, so it
cannot isolate page observation and is not presented as a sampling cost.

The source 0.6 atomic-inventory hard cut was rerun against the same PocketIC
binary after this 0.5 subject was recorded. It again reported 200 instructions
for both brackets and an observed delta of zero. Its linked candidate reported
20,947 scheduler instructions, 18,434 work instructions, and 30,732,311 cycles
for the dispatch. Those linked-candidate values are regression confirmation;
they do not replace or relabel the released 0.5 measurements above.

## Limits

- This is an observed PocketIC 15.0.0 call-context counter result, not a
  protocol ceiling or a promise that future IC metering assigns the same
  charge.
- The probe isolates the page reads named in the question. It does not claim a
  separate total for bounded snapshot aggregation, which occurs after the
  callback instruction interval.
- A trap or instruction exhaustion has no end observation and therefore no
  completed sample; this probe does not fabricate one.
- Page extents remain high-water observations in 64 KiB units, not exact live
  bytes.
