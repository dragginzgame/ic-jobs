# Typed registration setup

Status: delivered in 0.20.0 at `01031c912058089756aed87fafa4918476c12bd4`.
The preparation evidence below retains its original graph and scope; it does
not establish complete hosted acceptance for that later release graph.

Direct registration previously accepted `DeclarationLifetime` and
`Option<TimerSchedule>` independently. A remove-on-stop declaration with no
schedule reached a typed runtime error. The 0.20 hard cut makes that invalid
combination unrepresentable while preserving the
[atomic creation contract](0.18-atomic-registration.md).

## One configuration owner

All three `register_*` functions take `TimerStart`:

```rust
TimerStart::Retained { initial: None }
TimerStart::Retained { initial: Some(schedule) }
TimerStart::RemoveWhenStopped { initial: schedule }
```

The shared initial-registration owner decodes retention and the requested
schedule once. Retained inactive authority remains available for later control;
remove-on-stop authority always begins scheduled. Lifetime snapshots continue
to expose `DeclarationLifetime`, without becoming registration inputs or live
control authority. The old independent constructor arguments and
`TimerError::InitialScheduleRequired` are removed, without forwarders.

Schedule encoding/deadline validation still occurs before claim allocation.
An initial provider-binding or confirmation failure retires the exact new
claim and handles before dropping captures outside registry/provider borrows.
The callback factory remains owned through that cleanup. A provider trap has
normal IC message rollback; the enum adds no persisted intent or new recovery
path. Async ordinary work, command arbitration, cancellation, recurrence and
the separately committed Watchdog successor retain their existing contracts.

## Caller cut

Replace the old lifetime/schedule pair with its corresponding enum variant.
Direct retained callers with no first wake-up use `Retained { initial: None }`;
scheduled retained callers use `Some(schedule)` in that variant, and transient
callers supply `schedule` directly in `RemoveWhenStopped`.

Lifecycle `reconcile_*` signatures stay the same and create retained inactive
authority internally before reconciliation. The Jobs adapter uses those
helpers; Canic's direct registration callers/examples require the argument
update. Every linked owner must select one exact Timers package identity.
Sibling source/pins remain separately owned; no consumer files are changed by
this preparation. Native fixtures and the maintained runtime/size probes are
updated together in this repository.

## Qualification

The public compile-fail example rejects inactive remove-on-stop configuration.
Existing native subjects retain invalid duration/deadline rejection, no claim
allocation on rejection, duplicate/capacity failures, all policies/lifetimes,
binding/confirmation failures and capture destruction after cleanup. The
PocketIC rejection endpoint and its caller now exercise only representable
invalid schedules; the missing-schedule parameter/path is removed together.
Existing suspension, cancellation, abandonment, traps, Watchdog recovery,
upgrade reconstruction and policy cohorts remain required.

The approved locked/offline library compile-only check passes on Rust 1.99.0,
including library test targets, with incoming Metrics 0.7.3. The library also
passes a compile-only `wasm32-unknown-unknown` check with the prepared
Rust 1.88.0 compiler/target. With separate explicit approval, all 149 native
tests and nine doctests pass; the nine doctests also pass on Rust 1.88.0.
Library Clippy passes on Rust 1.99.0. Runtime/PocketIC probe Clippy and all four
size-probe Clippy selections pass on Rust 1.88.0, as do Wasm compile-only checks
of the runtime probe and each size cohort under the `timer-probe` profile.
The checks do not execute PocketIC, produce size measurements or establish the
complete release gate. Commands, logs and the source patch are retained in
`target/development/typed-start.rFyIOguo/`; the [release owner](../evidence/release-history.md#prepared-020-typed-constructor-hard-cut)
records the source/graph and scope. Cargo inputs and index entries are unchanged
by validation; its pending changelog was 0.20.0, finalized by the maintainer.
Canic is notified in its existing [coherent timer adoption issue](https://github.com/dragginzgame/canic/issues/33#issuecomment-6127168880).

No instruction or Wasm savings are claimed. Successful scheduled creation
still performs one provider arm. Live callback/handle ownership remains the
same by source inspection; actual footprint comparison requires the existing
cohorts at matched tools and dependency graphs. The release benefit is a
smaller constructor contract with the invalid lifetime/schedule pair removed.

## Prepared 0.21 lifecycle creation

Delivered in 0.21.0 at `a6b518722438d2f7e2dccd7ccfef07debc35b5b3`.
The [delivery owner](../evidence/release-history.md#021-delivery-and-issue-50-acceptance)
records the completed maintainer-operated gate; preparation observations below
retain their original identities and scope.

The maintainer approves extending atomic creation to the three lifecycle
reconciliation helpers. Previously their shared owner filled an empty slot with
inactive callback authority before applying the requested schedule. A typed
first-call error therefore left that callback installed; a later retry retained
it instead of installing the newly supplied callback.

The shared owner now creates authority locally, applies the requested initial
state through the existing policy-specific control operation, and publishes the
registration into an empty slot only on success. A failed first call invokes
the same exact-claim cleanup owner as direct registration. It clears provider
handles and removes the new declaration before captures drop, outside registry
and provider borrows. An already-expired exact claim counts as retired; a cleanup
error takes precedence over the original creation error, matching direct creation.
Registration sequences are never rewound, and independent operations performed
by capture destructors are not undone. Provider traps retain ordinary IC message
rollback; there is no await, persisted intent or new recovery protocol.

Successful inactive declarations remain intentionally retained. Successful
active creation preserves its policy-specific scheduling mode and deadline.
Existing-slot reconciliation still validates exact identity, policy and lifetime,
retains the original callback, and preserves authority on later errors. Its
unused replacement factory drops before control is applied, as previously;
destructors can issue timer commands, so that ordering remains significant.
No public signatures, result types or cadence/trap behavior change. This is a
semantic hard cut bundled into the existing **0.21.0** Metrics adoption draft.
Consumers must stop relying on a fresh error leaving a populated owner slot;
they retry from its empty state. Canic and Jobs callers retain their argument
mapping and separately owned dependency/qualification obligations.

Prepared native subjects cover all three policies' initial deadline overflow,
provider installation/confirmation faults, capture cleanup and retry callback
selection; Once also covers an unencodable duration. Existing-slot subjects
retain failed deadline and provider states, callback identity and successful
retry. A suspended ordinary subject verifies unused-factory destruction before
authoritative reconciliation. The maintained canister probe and PocketIC caller
cover returned initial schedule errors, empty owner slots, exact inventory
preservation, capture release with registry access and no later work delivery.
Native injection is not IC rollback evidence. Qualification is recorded with
its actual source/graph in the [release owner](../development.md).
The explicitly approved 0.21 focused checks pass: 154 native tests, nine
doctests on Rust 1.99.0 and 1.88.0, library/probe Clippy and runtime/four-cohort
Wasm compilation. No PocketIC execution or complete release result is claimed.
