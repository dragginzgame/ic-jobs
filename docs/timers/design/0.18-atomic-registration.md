# Atomic initial registration

The prepared [0.20 typed setup](0.20-typed-registration.md) supersedes this
constructor signature and missing-schedule runtime rejection. Its atomic
binding, retirement and capture-ownership contract remains applicable. The
details below retain the delivered 0.18 evidence and original API shape.

Status: delivered in 0.18.0 at `52bc4bad399122be040cf155d9b4563b5509e009`.
[Exact-source CI](https://github.com/dragginzgame/ic-timers/actions/runs/38159662258)
passes Linux, MSRV and both native macOS lanes. Independent downstream adoption
and matched footprint/cost comparisons remain separate obligations.

The concrete consumer requirement is Canic's lifecycle one-shot wrapper in
`crates/canic-core/src/workflow/runtime/timer/mod.rs`: it registers a callback,
requests its first wakeup, and unregisters on scheduling failure. Cleanup can
itself fail, so the application currently carries two errors. Timers owns both
callback registration and provider binding and can finish that operation before
returning authority. Canic's separate custody failure remains application-owned.

## Construction contract

Each direct registration accepts `initial: Option<TimerSchedule>` between
`DeclarationLifetime` and the policy-specific callback. There is one signature
per policy and no old-signature alias.

- `Some(schedule)` validates its duration/deadline before allocating a claim,
  installs the callback, binds and confirms one wakeup, then returns the claim.
- `None` installs an intentionally inactive retained declaration with no
  provider handle. Transient `None` returns `InitialScheduleRequired`.
- A returned scheduling or binding error leaves no authority or handle belonging
  to that failed creation. The exact claim is used for retirement; identity reuse
  must not remove an unrelated later claim.
- The factory retains callback captures through failed binding and claim
  retirement. Consumer destruction runs outside registry and provider borrows.
  Independent operations performed by a capture destructor are not rolled back.
- A provider trap is not a typed error. Normal IC message rollback applies to
  creation and other mutations in that message. This operation is synchronous
  and crosses no `await`; it introduces no stable intent or transaction framework.

The first deadline is explicit, independent of recurrence cadence. `After`
records the existing explicit relative mode (`Once`), and `At` records
`Deadline`; zero delay requests a later provider message, never synchronous
consumer execution. After-completion recurrence still starts from completion.
Watchdog still commits its cadence successor in the scheduler message before
queueing synchronous consumer work. Callback `ContinueImmediately` still uses
`Continuation`; an initial `After(0)` is not a callback continuation.

Later ensure/reconcile/cancel/unregister operations retain their established
arbitration, ownership and failure semantics. Lifecycle reconciliation keeps
observable retained declarations in caller-owned slots on later control failure.
An inactive retained declaration is intentional authority, not a creation leak.
Prepared 0.21 extends failed-creation cleanup to the first lifecycle
reconciliation: fresh slots are filled only after the requested initial state
succeeds. Existing slots retain the later-control behavior described here.
The [0.21 lifecycle owner](0.20-typed-registration.md#prepared-021-lifecycle-creation)
records the cut and qualification limits.
No automatic Drop cancellation, intervals, persistence, jobs, retries or new
runtime policy is added.

## Consumer cut

Direct callers pass their first request in registration and remove their
immediately following initial arm/compensating unregister branch. Deliberate
retained declarations pass `None`. Existing lifecycle reconciliation callers
need no new public argument. All libraries in a canister must select one exact
Timers package identity when adopting the minor line.

The maintained runtime probe and size cohorts use the new construction call.
The retained churn/capacity fixtures still deliberately declare inactive timers.
The [Canic owner mapping](../adoption/canic.md#operation-mapping) identifies the
specific consumer cleanup and its separate custody obligation. Sibling source
and package pins remain unchanged; owner adoption must follow the published cut.

## Qualification and acceptance

Prepared native subjects cover confirmed authority and exactly one wakeup,
invalid/missing schedules, capacity and duplicate rejection, both initial binding
and confirmation failures across all policies/lifetimes, and capture destructors
that inspect the registry and reuse the retired identity. Existing stale-claim,
mutation, suspension and callback-failure subjects remain required.

The PocketIC runtime probe adds typed invalid/missing-schedule rejection across
all policies, unchanged inventory and prompt capture release in a real IC message.
Existing immediate start, ordinary awaits/traps, Watchdog rollback/recovery,
upgrade reconstruction, cancellation and policy cohorts must pass against the
new probe. Native injected provider failures do not prove IC rollback.

Use the existing complete user-operated validation gate, MSRV, probe lint,
`pocketic-watchdog` and `pocketic-cohorts`. Do not infer macOS qualification from
Linux. Before release, compare all maintained cohort compressed Wasm sizes and
instruction observations against 0.17.14 with the same tool/lock inputs; preserve
any unmatched graph or measurement limits. There is no claimed performance win:
creation still arms one provider timer, retains the same live captures and handle,
and adds bounded input validation/retirement code. The expected benefit is removal
of consumer-side arm rollback, not a different scheduler complexity.

Acceptance requires all affected calls to use the current signature, negative
subjects to return typed errors without residual authority/handles, cleanup to
precede consumer Drop, and the complete existing recovery/cohort gates to retain
their guarantees. Release versions and lockfile mutation remain maintainer-owned.
