# Policy-specific callback authority and results

Status: the policy-specific capability and ordinary result splits are current.
The 0.12 hard cut extends the capability boundary to ordinary callback results;
preparation evidence and maintainer validation are scoped below.
The 0.8 deadline contract supersedes the original restriction on Watchdog
reconciliation below.

## Decision

The public callback capability is policy-specific. `register_once` and
`reconcile_once` pass `OnceContext`; the after-completion entry points pass
`AfterCompletionContext`; Watchdog entry points pass `WatchdogContext`.

This makes the policy contract visible in the callback signature and removes
runtime policy probing from consumer code. A Once context cannot request
configured recurrence, and a Watchdog callback cannot request an arbitrary
ordinary deadline or reconciliation in this original 0.5 contract. Since 0.8,
Watchdog has its own exact successor reconciliation; see the
[deadline contract](0.8-registration-continuity-and-deadlines.md). The three
types intentionally share no public generic marker, conversion, compatibility
alias, or escape hatch.

Each context stores its private exact callback token directly. The shared
claim-transition boundary validates identity, claim generation, callback generation
and work role before handle detachment or mutation. The public split changes which
operations can be expressed without changing authority lifetime: mutation still
expires as soon as the exact work attempt completes.

## Ordinary callback results

The 0.12 hard cut extends the policy boundary to returned futures:

| Entry points | Future output | Proposal |
| --- | --- | --- |
| `register_once`, `reconcile_once` | `OnceRunResult` | `OnceDecision` |
| `register_after_completion`, `reconcile_after_completion` | `AfterCompletionRunResult` | `AfterCompletionDecision` |

Both decisions support Stop, immediate continuation, relative retry and absolute
deadlines. Only `AfterCompletionDecision` has `RecurAfterCompletion`; cadence
still belongs to the registration. Once retains explicit rescheduling. Each
result keeps its fields private, reports its completion through `completion()`
and its proposal through `decision()`, and forces invariant failures to Stop.
Watchdog's synchronous result and scheduler/work contract are unchanged.

Public result rustdoc and the README explain that success, no work and retryable
failure preserve the supplied decision. Those classifications do not implicitly
select retry or recurrence. Relative-delay validation occurs when the runtime
selects a proposal after command arbitration, not at result construction;
configured recurrence checks its successor relative to completion time. This
documentation follow-up changes no runtime behavior and has source/formatting,
read-only metadata and diff review only.

The shared public `TimerRunResult` (including `new`, `completion`, `directive`)
and `TimerDirective` are removed. Their internal completion representation is
narrowed and renamed to crate-private `OrdinaryRunResult` in `callback` and
`OrdinaryDirective` in `schedule`. The resolver remains the canonical checked
deadline owner. These private values are neither compatibility APIs nor another
mutation path. No policy-result conversions, aliases or public generic marker
remain. `TimerDirectiveSnapshot` retains its observation meanings and accepts a
checked projection from either decision; it cannot convert back into a decision.

The runtime creates the original consumer future at callback acceptance, then
erases its normally returned result through the existing callback owner. The
registry still arbitrates authoritative commands before resolving a proposal;
winning reconciliation may discard an otherwise overflowing relative delay.
An explicit invariant failure always stops. Private erased-policy mismatch
validation and `DirectiveNotAllowed` remain internal corruption protection;
they are no longer a reachable policy mistake through the public result API.

Current examples, native fixtures and the ordinary-await/size probes use these
types directly. Positive doctests cover all four signatures; compile-fail
doctests cover crossed results/decisions and unavailable Once recurrence.
`make test` and `make msrv` now include API doctests. The gate fixture records
both command sequences through a Cargo substitute and injects command failure;
it does not establish compiler rejection. Native runtime cases exercise every
legal decision, duration/deadline overflow, invariant stopping and winning exact
reconciliation. Existing async suspension, lifetime, cancellation, generation
and Watchdog fixtures remain maintained.
The callback-borrow rejection fixture covers both typed ordinary factories and
both declaration lifetimes: it expects no consumer invocation or work sample,
retained invariant failure, or expiration after transient removal. Public live
recurrence cases check success, no work and returned retryable failure advancing
from completion time, and invariant failure stopping with the reported partial
work retained. Configured recurrence requires a normal return requesting it;
the completion classification need not be success. These additions remain
unexecuted and do not qualify ordinary trap recovery.

Preparation evidence is limited to source review, Rust formatting/parsing, shell
and embedded fixture-shell syntax, read-only changelog preparation and diff
checks. Automated preparation has not run compilation, doctests, native tests,
lint, PocketIC subjects or policy cohorts for this cut. The complete
maintainer-operated release gate remains required; old receipts do not qualify
new linked Wasm or instruction costs. Automated preparation did not change the
provider, toolchain, package version or lockfiles; the maintainer's minor bump
advanced Cargo identity and both lockfiles to 0.12.0.

The maintainer reported `redundant_pub_crate` lint failures for the internal
callback alias and directive enum. The first correction to `pub(super)` failed
the same lint because these modules are immediate children of the crate root.
Those declarations and the erased result now use unqualified `pub` within
private root modules; none is re-exported. This correction has source/formatting
and diff review only; successful lint re-execution remains maintainer-owned.

Ordinary downstream callers must adopt matching results in one coordinated
minor-version cut, and all linked owners must resolve one exact package identity.
External consumer mutation remains outside this repository's authorized scope;
their current heads and adoption are not qualified here. There is no persisted
library format to migrate, and the hard cut introduces no storage reader.

## Ordinary delivery abandonment

The 0.13 hard cut adds a public `InactiveReason::Abandoned` observation and changes
the terminal lifecycle of dropped ordinary deliveries. The maintainer's 0.13.0
bump, release commit and tag record that minor package identity. The current
0.13.1 notes reconcile documentation with that release without changing the
contract, Cargo versions or lockfiles. The tag alone does not establish native,
PocketIC, host or cost qualification; recorded evidence retains its scope below.

The private delivery guard is constructed when arming the provider future, before
its first poll. Normal dispatch completion disarms it. Otherwise it validates
the exact claim, ordinary role, callback generation and confirmed delivery state.
Scheduled authority also requires the still-owned handle: a detached handle belongs
to its synchronous transition owner. Explicit cancellation, replacement, stale
delivery and failed unconfirmed binding therefore do not produce abandonment.

Retirement uses no provider operations. It discards pending scheduling commands,
records Unacknowledged without a completion or measurement, and leaves a retained
claim inactive with Abandoned/Failed observations. Transient declarations and
pending unregistrations are removed. Removed callbacks are returned to the runtime
so capture destructors run after releasing the registry borrow. Those destructors
must be bounded, nontrapping and safe in CDK cleanup; they must not arm timers there.

An owner may explicitly rearm a retained abandoned declaration. This does not
recover application effects committed before an await and does not imply a retry.
A live pending future still owns Running state; cancellation and unregister
continue to wait for its normal completion or destruction. Watchdog's synchronous
prearming protocol is unchanged.

Native fixtures cover pre-poll/running future drop, both policies/lifetimes,
pending commands, stale generations/identity reuse, full-capacity release and
capture destruction outside the registry borrow. Native drop is not simulated
IC rollback. The ordinary probe also retains real call awaits and injects traps
before the first await or after gate release. PocketIC checks inactive/removed
authority, expired contexts, absent completion/samples, capture release, retained
rearm or identity reuse, and independent Watchdog progress.

These additions have source and Rust formatting/parsing review only. Compilation,
lint, native execution, pinned PocketIC qualification, policy-cohort Wasm/instruction
deltas and required host qualification remain maintainer-owned and pending. In
particular, cleanup behavior must not be claimed from the native fake or historical
Watchdog receipts.

The maintainer's broad native run aborted during thread-local destruction in
`removed_transient_claim_cannot_report_wakeup_liveness`: its replacement Once
timer remained armed, and dropping the queued delivery accessed an already
destroyed runtime TLS slot. Runtime fixtures now retain a scoped cleanup guard
that drops queued and suspended fake tasks before TLS teardown. The fake detaches
its task map before dropping futures, so capture destructors can inspect it
without a conflicting borrow. A focused fixture covers both pre-poll and
suspended work, capture release, available runtime TLS and an empty queue after
cleanup. Source review does not establish execution; the maintainer's rerun
remains pending. Production guard behavior is unchanged, and native fixture
teardown is neither canister lifecycle evidence nor simulated IC rollback.

One inspected adopter, Toko Miner's
`apps/toko_miner/game_shard/src/observability/mod.rs::inactive_reason_label`,
exhaustively matches `InactiveReason` and must add an `Abandoned` projection when
adopting the 0.13 identity. Sibling pins inspected during preparation were older
0.11 identities; they are historical usage evidence, not current adoption or
composed qualification. Sibling mutation is outside
this repository's authorized scope. Adoption must also account for ordinary
Unacknowledged observations without interpreting them as Watchdog recovery.

## Request ordering

The removed request counters were not sequence numbers in the operational
sense: no transition compared, inspected, or projected them. Incrementing the
counter could only add an artificial overflow failure.

Actual ordering remains explicit:

- callback generations invalidate stale provider delivery;
- the ordinary registry entry owns one pending command and applies its closed
  ensure/reconcile/cancel/unregister precedence;
- the Watchdog control owns one pending command while work runs; and
- normal callback completion applies that selected command before retaining or
  clearing a successor.

Removing the unused counters does not weaken stale-callback rejection or add a
second pending machine. Generation exhaustion remains checked because those
generations are carried by callbacks and compared with canonical ownership.

## Compatibility boundary

This is a pre-1.0 hard cut and therefore opens 0.5.0. `TimerContext`,
`TimerError::WrongPolicy`, and
`TimerControlFailure::RequestSequenceExhausted` are removed outright. Current
tests and contract documentation move to the typed API; historical release
notes may retain the old names as records of earlier behavior.

The callback-authority change does not alter provider binding, timer schedules,
lifecycle reconstruction, or the Watchdog scheduler/work protocol. Apart from
the removed impossible control failure and the bounded memory observations
below, existing snapshot meanings are unchanged. Real-canister recovery
guarantees remain those established by the existing PocketIC evidence.

## Memory page observations

The same 0.5 snapshot line adds bounded page-extent measurements beside the
instruction aggregates. Runtime dispatch samples Wasm linear memory and stable
memory in 64 KiB pages before starting the instruction delta and again after a
normally completed scheduler or work path. Sampling and retention use only
fixed-size copy values. The page reads sit outside the instruction-delta
interval so the established instruction meaning does not absorb observation
overhead.

Each role retains a saturating sample count, its latest start/end extents, and
maximum observed non-negative start-to-end growth for Wasm and stable memory.
It does not sum absolute page counts. A trap or instruction exhaustion cannot
commit the end sample, so the runtime records no memory sample for that attempt
just as it records no instruction sample.

Watchdog work and the scheduler are synchronous. Ordinary work may await, so
its extent change can include other canister activity interleaved before the
future completes. The summary therefore reports an observed interval and does
not claim exclusive allocation attribution to consumer work.

These values are page extents, not exact live allocation. Both memory extents
are monotonic within one runtime epoch, while allocator liveness within the
final page is invisible to `ic-timers`. A consumer that needs byte-level
liveness must combine the extent with an owner-derived bound; the timer runtime
does not invent one.

## Focused evidence

Native tests use fixed fake page counters to prove exact start/end retention,
separate scheduler/work maximums, saturating sample counts, and the absence of
a sample when completion accounting traps. Recorded focused PocketIC 15.0.0 tests
execute the real Wasm system operations: both intentional Watchdog work failure
and 40-billion-instruction exhaustion leave a normally completed scheduler
sample but no work sample, and the next successful cadence records coherent
scheduler and work page extents.

The current host harness uses `ic-testkit` with PocketIC 16; the recorded subjects
above require renewed execution. See the
[harness qualification scope](../evidence/release-history.md#testkit-harness-qualification).

The provider binding and two-message Watchdog protocol are unchanged. The
complete recovery matrix and policy cohorts therefore remain release-gate
evidence rather than being repeated for this focused observation change.
