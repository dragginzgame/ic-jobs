# 0.3.1 hardening

Status: released as 0.3.1 on 2026-08-14

## Objective

Close the concrete post-0.3.0 audit findings without changing the public timer
model or weakening the two-message watchdog protocol.

## Runtime hardening

- Unexpected internal callback completion, provider ownership, cleanup, and
  accounting failures no longer return normally without disposition.
- An unexpected watchdog-work failure traps its current message. IC rollback
  therefore preserves the successor committed by the earlier scheduler
  message; native fault injection verifies the failure cannot be silently
  accepted, while PocketIC remains the authority for message rollback.
- Provider-cleanup borrow failure is returned and tested rather than
  discarded.
- The IcyDB-shaped fixture drives retryable continuation and durable terminal
  failure through real scheduler and work callbacks, checking counters,
  successor retention, completion partitioning, and terminal clearing.
- `OnceRegistration`, `AfterCompletionRegistration`, and
  `WatchdogRegistration` are `must_use` sole-owner capabilities.
- `Once` and `AfterCompletion` claims can authoritatively reconcile an exact
  optional schedule, and the public `reconcile_once` helper reconstructs that
  capability from consumer-owned lifecycle state.
- The registry is now the sole pending-command authority for ordinary timers.
  `TimerControl` retains checked generations and immediate transitions but no
  duplicate pending machine; focused tests fix later-deadline replacement and
  nested reconcile/ensure ordering.

## Canic adoption boundary

- `docs/adoption/canic.md` freezes deterministic `TimerKey` identities,
  fallible public-facade changes, the 96-to-64-byte label hard cut, claim and
  directive mapping, and removal of Canic's provider/state/metrics duplicates.
- Canic log retention and cycle top-up remain ordinary after-completion work;
  they do not pay for or claim watchdog recovery.
- No global suspend/resume API is added. Canic must cancel only its own claims
  and rerun its domain reconcilers on resume, so a shared registry cannot let
  one consumer suspend IcyDB or application-owned timers.
- The Canic mapping recorded here was subsequently corrected by the 0.3.2
  review; see `docs/changelog/0.3.2.md` for the maintained adoption contract.

## Release hardening

- Version bumps update both `Cargo.lock` and `testing/Cargo.lock`, then run
  cheap offline locked-metadata checks for both workspaces without repeating
  the pre-mutation evidence suite.
- `release-stage` stages both lockfiles, and regression checks freeze that
  wiring.
- Release evidence accepts only the audited `pocket-ic-server 15.0.0` binary
  with SHA-256
  `29472ea4433b30a280676c4e22e369d79d5ba6ee1b4d48bab32ebe7d0ad2b4bb`.
- With no override, the release flow installs that exact Linux x86_64 artifact
  into the ignored `target/tools` cache. Explicit `POCKET_IC_BIN` paths remain
  strict and are never overwritten.
- Normal CI enforces that every direct `ic-cdk-timers` reference remains in
  the private `platform` module and that neither the provider nor its boundary
  is re-exported.
- Automated-contributor guidance makes superseding pre-1.0 changes hard cuts
  by default, without hidden compatibility paths.

## Evidence

Before the ordinary-reconciliation slice, the complete `release-verify` gate
passed with 58 native tests, Rust 1.88, warning-denied Clippy and rustdoc,
native and Wasm compilation, offline packaging, every nested probe
configuration, six watchdog/recovery PocketIC tests, and all four comparable
policy cohorts.

The tagged release was produced by the guarded maintainer-owned flow, which
requires `make ci`, Rust 1.88 compilation, every nested probe lint
configuration, the complete PocketIC watchdog suite, and all policy cohorts
before version mutation.

This patch does not claim IcyDB or Canic adoption. It makes Canic's remaining
dependency-unification, provider-inventory, adapter, and integration gates
explicit without changing downstream repositories.
