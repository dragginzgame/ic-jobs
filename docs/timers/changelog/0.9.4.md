# 0.9.4 ordinary completion ownership

Status: released 0.9.4.

## One completion state owner

`TimerControl::complete` previously updated registration state and returned
another action describing that state. Its cancellation argument was returned
unchanged through a completion-only action variant; the registry already owned
the pending command that supplied it. The registry also manufactured fallback
schedule metadata when translating an arm, although successful completion with
a successor necessarily had a selected schedule.

Completion now returns only `Result<(), TimerControlError>`. Checked generation
allocation still precedes mutation, and stale completion still leaves control
unchanged. The registry constructs the provider effect from the resulting
registration and selected schedule, with the initial arm kind appropriate after
ordinary work consumes its wakeup. Cancellation observations are determined
directly from the authoritative pending command. Unexpected state/metadata pairs
retain typed terminal cleanup instead of manufacturing a successful schedule.

The completion-only action and cancellation argument are deleted, including
their request/cancellation match branches and old fixture assertions. No new
type, compatibility alias, state machine or alternate completion implementation
is added. Public contracts, snapshot shape, generation exhaustion, pending-command
precedence, transient removal and provider-failure recovery remain unchanged.

## Focused verification

Existing control fixtures now assert resulting scheduled/unregistered state,
allocated generation, stale-completion rejection and stopping after generation
exhaustion. The registry's existing
`nested_cancel_and_ensure_use_latest_request_order` fixture additionally checks
that a winning cancellation increments its counter once and a later ensure
supersedes cancellation without another increment.

Existing ordinary reconciliation, recurrence, unregister, declaration-lifetime
and provider-binding fixtures remain the focused behavior checks. Rust was
formatted; diff whitespace and local documentation links were checked. These
fixtures, builds and lint gates were not run in this follow-up and remain
maintainer-owned. No new runtime, IC recovery or performance result is claimed.
