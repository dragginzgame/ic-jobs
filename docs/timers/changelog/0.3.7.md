# 0.3.7 code hygiene and module boundaries

Status: released 0.3.7.

## Scope

- Keep the public facade limited to runtime capabilities and provider-neutral
  schedule/snapshot values.
- Keep `control`, `registry`, the runtime implementation, and `platform`
  private; `ic-cdk-timers` remains solely behind `platform`.
- Remove the unused public `TimerFuture` implementation alias as a pre-1.0
  hard cut. Generic callback registration remains unchanged.
- Consolidate ordinary callback erasure and duration-to-nanosecond validation.
- Align code and maintained documentation comments with actual declaration
  lifetime, armed-handle, scheduling-mode, and result-validation semantics.
- Avoid duplicate hosted validation: pull requests and `main` retain full CI
  and MSRV jobs, while tag pushes verify release truth, the exact version tag,
  and reachability from `main` without repeating Rust builds.
- Warn before a bump when compact-status prose may become stale, while keeping
  that semantic check strictly advisory and incapable of blocking a release.

## Runtime impact

No registry transition, provider protocol, callback message boundary, snapshot
shape, counter, or persisted state changes. PocketIC recovery evidence is not
repeated for this source-organization, CI, and documentation patch; the full
suite remains part of `release-verify`.

## SemVer follow-up

Removing the public `TimerFuture` alias in 0.3.7 was breaking within Cargo's
0.3 compatibility line and should have targeted 0.4.0. The alias remains
removed: restoring it would violate the hard-cut policy. Future public removals
advance the minor line, while this note records the published mistake.
