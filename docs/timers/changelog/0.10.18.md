# 0.10.18 borrowed transition identities

Status: released 0.10.18.

## Identity custody

Registry cancellation, ordinary and Watchdog completion, unregistration,
registration failure cleanup and claim-scoped provider detachment borrow identity
from the supplied claim or callback token. They no longer clone an identity into
a temporary local solely for subsequent lookup, removal or further cloning.
Ordinary terminal cleanup and optional wakeup clearing also borrow the identity;
an owned copy is created only when a clear effect is actually emitted. Inactive
cancellation and initial generation-exhaustion paths no longer copy an identity
for a `None` effect.

The supplied claim or token remains alive throughout each synchronous operation.
Its identity is independent of the registry entry being mutated or removed, so
removing an entry does not invalidate that borrow. No identity reference escapes
into a queued effect, snapshot or detached handle. Those values still create
owned tokens and identities at their existing custody boundaries.

Exact-claim checks, callback roles and generations, pending-command arbitration,
completion classification, lifetime removal, cleanup order and rollback rules
remain unchanged. This introduces no shared identity allocation, registry cache,
public alias or compatibility path. Public API and snapshot values are preserved.
The removal of intermediate copies is established by source inspection; no
allocation, instruction or performance savings were measured.

## Verification and delivery scope

The existing fixtures already exercise observable identity and capability
behavior. Focused maintainer subjects include:

- Registry ordinary and Watchdog lifetime/failure matrices, scheduled/running
  unregistration, stale claim rejection and provider-role detach/restore.
- Runtime identity reuse, nested and suspended control, provider binding failure,
  detached-handle restoration and claim retirement after transition failure.

These fixtures retain their current assertions. No new test mirrors borrowing
syntax or searches for the removed local copies. Tests, builds, lint gates and
deployment validation remain maintainer-owned and were not run. Native fixtures
do not establish IC rollback; existing PocketIC subjects remain required.
Changed Rust was formatted; diff whitespace and read-only changelog and
release-truth checks passed.

This private cleanup fits 0.10.18. Cargo remains at 0.10.17, both lockfiles and
dependencies are unchanged, and the changelog heading stays undated. Version
mutation, staging and all Git/release execution remain maintainer-owned.
Downstream work remains deferred.
