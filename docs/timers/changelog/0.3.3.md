# 0.3.3 runtime and release hardening

Status: released 0.3.3.

## Runtime authority

- `TimerContext` now carries the exact private callback token rather than only
  the longer-lived registration claim generation.
- Nested ensure, reconcile, and cancellation remain valid while consumer work
  is running. The same calls return `RegistrationExpired` after that exact
  work attempt completes, including when a successor is already armed.
- Focused ordinary and watchdog tests retain a context across completion,
  prove that it cannot clear or replace the next generation, and then run that
  successor normally.
- Public registration and lifecycle transitions now fail the affected claim
  closed if provider-handle installation or effect confirmation fails. A
  retained declaration records `ProviderBindingFailed` instead of remaining
  falsely scheduled and can recover through a later explicit ensure.
- Fault injection replaces an already armed `Once` callback, forces provider
  installation failure, proves both old and new provider arms are cleared,
  verifies truthful counters/state, and then successfully retries.

## Release hygiene

- Explicit release targets must be strictly greater than the workspace
  version. Canonical numeric SemVer components reject leading zeroes, and the
  existing-tag check resolves only the exact `refs/tags/vX.Y.Z` name.
- Release-gate regression checks exercise both rejection paths before any
  expensive validation or version mutation.

## Evidence

The focused context-expiry and provider-binding tests plus all 65 native tests
pass. Normal CI passes with warning-denied Clippy, rustdoc, Wasm compilation,
offline packaging, provider-boundary checks, and release-helper tests. Rust
1.88 workspace compilation and every supported nested-probe lint configuration
also pass.
