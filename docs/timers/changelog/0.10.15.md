# 0.10.15 accounting and effect simplification

Status: released 0.10.15.

## One completion representation

The four private classified counters own completed-work accounting:
`succeeded`, `no_work`, `retryable_failure` and `invariant_failure`.
`TimerCounters::work_completed()` returns their saturating sum. The separately
stored total, its initialization and its increment are removed.

The registry remains the sole production writer. Each completion increments
exactly one classified counter, starting from zero. Consequently, the derived
total equals the previous independently saturated total for every reachable
completion history. If a class or their sum reaches `u64::MAX`, both totals remain
saturated. No scan, cache or alternate accounting path is introduced.

Starts, scheduler callbacks, dispatched work, unacknowledged attempts and
measurement samples retain their independent counters and meanings. Completion
classification, lifetime decisions, failure handling and provider effects are
unchanged. This does not strengthen interruption or rollback guarantees.

The public getter and probe wire DTOs remain unchanged. The removed field was
private volatile state, with no library persistence codec or public construction
path. No generated binding, storage migration or compatibility alias is needed.
The derived Debug output no longer includes that private field.

## One effect application path

`apply_effect` performs wakeup binding and Watchdog dispatch directly inside its
matched effect branches. The single-caller `arm_wakeup` and
`dispatch_watchdog_effect` helpers are deleted, along with their repeated variant
matches and unreachable mismatch exits. The canonical effect remains available
for confirmation; no separate token/delay representation or dispatcher is added.

Shape validation still precedes handle cleanup and provider calls. Wakeup
replacement still clears the old wakeup, restores remaining detached handles,
binds the new handle and confirms it; confirmation failure clears that handle.
Watchdog dispatch still clears superseded handles, binds the cadence successor
before immediate work, then confirms both. Work-binding or confirmation failure
still clears the installed handles. Installation rejection still clears the
rejected raw provider handle after releasing the registry borrow.

Provider installation, confirmation and running-work authorization retain their
distinct state and generation checks. Public-control retirement and Watchdog
completion rollback rules remain separate. No public API, wire DTO or callback
scheduling contract changes.

## One memory extent representation

The private platform read returns the existing inert `MemoryPageExtent` value.
Callback measurement start/end records retain that value, and the registry pairs
the extents directly into `MemoryPageSample`. The duplicate `MemoryPages` type,
its getters and the registry's `memory_sample` conversion helper are deleted.
The native platform mock returns the same representation as production.

Both representations carried only Wasm and stable page counts in 64 KiB units;
neither held handles or runtime authority. No validation or normalization was
performed by the removed conversion. Constructors remain internal. The platform
still owns system reads; the registry still owns sample routing and aggregate
updates. This shares an inert value, not a provider capability.

The start page read remains before the opening instruction counter, and the end
page read remains after the closing counter. Native and Wasm branches, ordinary
await behavior, missing-completion handling, non-negative growth and saturating
summaries remain unchanged. No public snapshot layout, wire DTO, generated
artifact, persistence format or sampling-cost guarantee changes.

## Verification and delivery scope

The test-only `completion_partition_is_valid` checker is deleted: equality with
the derived total would now be tautological. Existing registry and runtime tests
retain concrete completion, failure, cleanup and lifetime assertions. The nested
Once and IcyDB-shaped lifecycle fixtures assert their actual outcome counts.

The counter fixture checks each classified outcome and the total, then seeds a
near-limit classification and records mixed outcomes across saturation. The
existing saturation fixture also checks saturation of all four classifications.
No source-string anti-resurrection assertion is added.

Maintainer execution reported 118 passing native subjects and a failure in
`watchdog_terminal_failures_respect_declaration_lifetime`. Its replacement
assertion incorrectly equated all completed work with invariant failures. The
completion cases return success before successor allocation exhausts its
generation; completion accounting retains that success while control stops with
`GenerationExhausted`. The fixture now checks the successful completion count
and zero invariant completions separately from the existing terminal-control,
cleanup and lifetime assertions. Production behavior is unchanged. A rerun of
the corrected fixture remains pending maintainer execution.

Focused maintainer verification is the counter tests plus the changed registry
and runtime subjects: nested Once scheduling, Watchdog terminal failures,
callback-borrow failure, failed dispatch and lifecycle reconstruction. Existing
PocketIC subjects remain deployment evidence; native counter inspection does
not establish IC rollback.

The effect cleanup reuses the maintained malformed-role/cross-claim rejection,
provider-install failure, confirmation failure, replacement/restoration and
Watchdog dispatch-failure subjects. Their assertions already cover observable
ordering and cleanup rather than the deleted helper names. No new test duplicates
the moved code. These tests remain pending maintainer execution.

For memory extents, the maintained Once fixture checks exact start/end Wasm and
stable pages and instruction observations after simulated growth. The bounded
measurement fixtures cover separate scheduler/work roles, growth and saturation;
the Watchdog completion-fault fixture preserves the absence of work samples.
The policy-role mismatch fixture still rejects measurement routing without
updating either aggregate. No extra test mirrors the deleted representation.

The follow-up inspection retained separate scheduler/work generations, pending
command states and provider authorization checks because they protect different
delivery, suspension and recovery contracts. Public directive-to-snapshot
conversion also remains a validation boundary; it must continue rejecting
unrepresentable durations independently of runtime scheduling. Downstream
repositories and fresh PocketIC behavior were not audited in this follow-up.

Tests, builds, lint gates and deployment validation remain maintainer-owned and
were not run. Changed Rust was formatted; diff whitespace and read-only changelog
and release-truth checks passed. No fresh runtime or performance result is claimed.

This private simplification fits 0.10.15. Cargo remains at 0.10.14, both lockfiles
and dependency versions are unchanged, and the changelog section stays undated.
Version mutation, staging and all Git/release execution remain maintainer-owned.
Downstream work remains deferred.
