# 0.6.1 measurement calibration

Status: released 0.6.1.

## Scope

- Clarify that scheduler and work instruction aggregates cover the accepted
  `ic-timers` execution interval, not application code alone and not the
  complete IC message.
- State the excluded work explicitly: provider dispatch before entering the
  runtime, provider return/reply work, start/end memory-page reads, and the
  post-interval bounded summary update.
- Require real message-level trap or instruction-exhaustion evidence for hard
  IC instruction-limit claims; library aggregates are operational telemetry,
  not a complete-message safety proof.
- Require consumers that need a durable terminal audit receipt for a removed
  `RemoveWhenStopped` declaration to own it outside the volatile timer
  registry. Do not add tombstones or another authority.
- Freeze IcyDB's exact-0.6 rebaseline guidance without claiming downstream
  adoption: identify the exact artifact and measurement interpretation,
  retain its external 40-billion-instruction exhaustion evidence, and require
  one exact resolved `ic-timers` package in a combined Wasm.

## Calibration evidence

The optimized PocketIC cohort now runs two fresh one-second Watchdog subjects:

| Profile | Full-message instructions | Scheduler interval | Work interval | Unaccounted difference | Two-message cycles |
| --- | ---: | ---: | ---: | ---: | ---: |
| Minimal | Unavailable | 20,944 | 18,275 | Unavailable | 30,730,996 |
| Bounded representative | Unavailable | 20,976 | 1,918,290 | Unavailable | 32,626,842 |

The bounded representative body performs 100,000 deterministic integer-mixing
steps and returns `Success(1) / Continue`. It is a reproducible synchronous
calibration load, not IcyDB database logic or a production instruction budget.

PocketIC 15's public Rust client and subnet metrics do not expose the exact
instruction total for each uninstrumented timer-generated update message.
Accordingly, the table leaves the full-message and residual columns
unavailable instead of converting cycle-balance changes into instruction
estimates. Two consecutive runs produced identical rows on
`pocket-ic-server 15.0.0`, SHA-256
`29472ea4433b30a280676c4e22e369d79d5ba6ee1b4d48bab32ebe7d0ad2b4bb`.

## Compatibility and release boundary

The current candidate changes repository documentation and test-only probe
code. It does not change the published crate source, public API, provider
binding, registry state machine, or two-message Watchdog protocol.

Repository-only work normally stays untagged because exact-pinned consumers
must coordinate every package identity. The maintainer explicitly selected
0.6.1 for this evidence update, so the release helper now warns about that
cost and continues through the complete release gate instead of refusing the
bump. No artificial crate change is added merely to trigger publication.
