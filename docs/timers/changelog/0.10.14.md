# 0.10.14 callback claim ownership

Status: released 0.10.14.

## One claim representation

Private callback tokens now contain a `RegistrationClaim` together with callback
generation and role. Token identity and exact-claim comparison use that contained
claim. Context control, Watchdog scheduler detachment, successor replacement,
completion detachment and callback binding-failure cleanup borrow it directly.
They no longer reconstruct a claim by copying identity and claim generation.

`RegistrationClaim::from_callback`, the context's claim-construction helper and
the callback-to-claim provider-failure forwarder are deleted. Owned queued
deliveries still clone their tokens, with explicit token cloning preserving all
claim, callback-generation and role fields. Neither the internal registration
claim nor the public registration capabilities gain a Clone implementation.

Borrowing a token's claim does not authorize a context mutation by itself.
Context control still validates exact running work before detaching handles:
identity, registration generation, callback generation, role and active state
must match. Completion keeps its running-work check. Provider restoration,
consumption and confirmation retain their separate ownership checks.
Binding-failure retirement remains scoped to the exact claim; unexpected Watchdog
work completion failures still follow the existing rollback rule.

The representation is private and volatile. Public API, snapshots, error
classifications, cancellation ordering, provider effects and declaration
lifetimes are unchanged. No storage migration, generated artifact or
compatibility alias is introduced.

## Verification and delivery scope

The existing registry running-work negative fixture constructs wrong claim and
callback generations through the token constructor, preserving its rejection
and no-mutation assertions. Role mismatch and completed-token cases remain.
The maintained provider-role/detachment and cross-claim dispatch-confirmation
fixtures continue to exercise cloned and reconstructed delivery tokens.

Focused runtime subjects include retained Once and Watchdog context expiration,
nested context cancellation/scheduling, stale identity reuse, Watchdog successor
replacement, binding rejection, handle restoration and dispatch failures. Existing
ordinary suspension and Watchdog PocketIC subjects remain deployment evidence.
No test whose sole purpose is to prohibit the removed helper is added.

Changed Rust is formatted. Diff whitespace and read-only release-metadata checks
passed. Tests, builds, lint gates and deployment validation remain maintainer-owned
and were not run. No fresh rollback or performance evidence is claimed.

This private simplification fits 0.10.14 without a 0.11.0 public hard cut. Cargo
remains at 0.10.13, both lockfiles and dependency versions are unchanged, and the
changelog section stays undated. Version mutation, staging and all Git/release
execution remain maintainer-owned. Downstream work remains deferred.
