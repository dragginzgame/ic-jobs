# 0.10.2 provider binding ownership

Status: released 0.10.2.

## Rejected handle cleanup

One private runtime `bind_provider_handle` consumes each raw provider handle.
Successful installation transfers it to the canonical registry. Any rejection
clears that handle after releasing the registry borrow and returns the original
typed error. The old runtime operation returning a rejected handle to its callers
and their repeated cleanup branches are removed.

Initial/replacement arms, Watchdog successor and work binding, and detached-handle
restoration use this operation. The registry still returns rejected handles at
its provider-neutral validation boundary; it performs no platform calls.

Watchdog successor installation still precedes work creation. A work-installation
failure still clears the installed successor separately. Work binding and dispatch
confirmation now share one cleanup exit: confirmation runs only after successful
work installation, and either failure clears the remaining entry handles.
The existing dispatch fixture covers both failures, no armed wakeup or queued
work afterward, and unchanged zero dispatched/started-work counters. Effect
confirmation, claim retirement, draining all detached handles after a restoration
failure and Watchdog work's trap/rollback rule retain their existing ordering and
behavior.
Public API and observations are unchanged; this is a private patch simplification.
