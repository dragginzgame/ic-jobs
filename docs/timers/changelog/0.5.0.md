# 0.5.0 policy-specific callback authority

Status: released 0.5.0.

## Implemented scope

- Replace the shared public `TimerContext` with concrete `OnceContext`,
  `AfterCompletionContext`, and `WatchdogContext` callback capabilities.
- Expose only policy-valid operations:
  - `OnceContext`: identity, explicit `ensure_scheduled`, exact schedule
    reconciliation, and cancellation;
  - `AfterCompletionContext`: identity, configured-cadence
    `ensure_scheduled`, exact schedule reconciliation, and cancellation; and
  - `WatchdogContext`: identity, configured-cadence `ensure_scheduled`, and
    cancellation.
- Preserve exact callback-token validation. A context retained beyond its work
  attempt still exposes inert identity but cannot mutate a successor or reused
  registration.
- Remove public `TimerError::WrongPolicy`; consumers cannot call a method for
  another timer policy. Defensive private policy mismatches are ownership
  invariants.
- Remove ordinary and Watchdog request counters and the public
  `TimerControlFailure::RequestSequenceExhausted` observation. The counters did
  not order requests: callback generations reject stale execution, while the
  registry's single pending command applies the established cancel, ensure,
  reconcile, and unregister precedence.
- Sample Wasm linear-memory and stable-memory extents at callback start and
  normal completion without allocation. Scheduler and work roles each retain
  only sample count, the latest start/end 64 KiB page extents, and maximum
  observed start-to-end growth for each memory. Absolute extents are not
  totaled, and a trapped or exhausted callback commits no sample. Async
  ordinary samples may include interleaved canister activity while awaiting.
- Route the paired instruction/page record from the callback token's canonical
  role through one registry path, so callers cannot select a contradictory
  measurement role. A policy/role mismatch fails as an ownership invariant
  rather than silently discarding the record.
- Describe page extent as a monotonic high-water observation, not exact live
  bytes. Sub-page allocator liveness remains consumer-owned and requires an
  owner-derived byte bound.
- Preserve one bounded registry, one provider path, exact handle ownership,
  lifecycle reconstruction, snapshots, counters, and the two-message Watchdog
  protocol.

No compatibility alias, deprecated forwarder, policy-probing method, alternate
registry, or provider fallback is retained.

## Migration

- Change explicitly named `TimerContext` callback parameters to the context
  required by the registration function. Inferred closure parameters need no
  source annotation change.
- Replace `context.ensure_once(schedule)` with
  `OnceContext::ensure_scheduled(schedule)`.
- Replace `context.ensure_recurring()` with
  `AfterCompletionContext::ensure_scheduled()` or
  `WatchdogContext::ensure_scheduled()`.
- Delete consumer matches for `TimerError::WrongPolicy` and
  `TimerControlFailure::RequestSequenceExhausted`. A former wrong-policy call
  is a compile-time API mismatch and should not be translated at runtime.
- Exact-pin adopters must update Canic and IcyDB to the same 0.5 package before
  qualifying a combined Wasm, because two resolved versions create two
  registries.

## Evidence

Normal CI passes with 84 native tests, warning-denied Clippy and rustdoc, Wasm
compilation, offline packaging, and the provider/release guards. Rust 1.88
passes the complete workspace and every supported nested probe
configuration.

Owner-local tests cover nested control and expired callback authority for all
three policy-specific contexts, bounded memory-page aggregation, live
start/end work sampling, and omission after a trapped completion path, in
addition to the existing policy, provider-failure, snapshot, lifecycle, and
Watchdog protocol suites.

Focused PocketIC 15.0.0 tests execute the real Wasm memory-size operations.
After either an intentional Watchdog work trap or 40-billion-instruction
exhaustion, the normally returned scheduler has one coherent memory sample and
work has none. The following successful cadence has two scheduler samples and
one coherent work sample. The complete recovery matrix and policy cohorts were
not repeated because this change does not alter the provider binding or
scheduler/work protocol; the maintainer-owned release gate retains both
suites.
