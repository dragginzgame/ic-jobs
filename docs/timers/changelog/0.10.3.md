# 0.10.3 running-work ownership

Status: released 0.10.3.

## One running-work invariant

The private registry entry owns one `owns_running_work` predicate. Registry
lookups select the entry by token identity before validating its exact claim,
policy-specific work role, callback generation and running state. Ordinary
scheduled callbacks and Watchdog dispatched-but-unstarted work have no running
authority; scheduler tokens never have work authority.

Callback lookup and delegated-context validation use the read-only entry lookup.
Ordinary and Watchdog completion use the mutable lookup and the same predicate
before any mutation. The old ordinary completion generation check and Watchdog
completion attempt/status check are removed. Watchdog completion still extracts
its authoritative successor from its policy-specific state.

Callback acceptance still owns the scheduled/dispatched-to-running transition.
Provider binding validates armed or dispatched state rather than running work.
Measurements may be recorded after completion and retain their exact-claim fence.
Those distinct boundaries are not merged into running-work validation.

Public API, typed stale-callback errors, command arbitration, counters, declaration
lifetimes, provider ordering and rollback rules are unchanged. This is a private
patch simplification with no compatibility alias or parallel validator retained.
