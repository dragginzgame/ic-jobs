# 0.10.6 transition and pending-command ownership

Status: released 0.10.6.

## One checked ordinary arming operation

Ordinary scheduling and completion previously repeated generation allocation
and the assignments that install a scheduled deadline. Both now call one
private `TimerControl::arm_deadline` operation. It checks the next generation
before mutating either the allocator or registration.

Request eligibility remains separate: ordinary ensure retains an earlier
deadline, exact reconciliation can replace it, and completion follows the
registry's exact running-token authorization and successor selection. Stopping
allocates no generation. Cancellation still invalidates a scheduled generation
without changing running work. Checked failures retain their existing behavior.

## Pending commands belong to awaiting work

Private Watchdog control previously stored a pending command independently of
its state, although only awaiting work could carry a command. Every transition
out of awaiting work had to clear that field explicitly.

`WatchdogState::AwaitingWork` now owns the command through both its dispatched
and running phases. Reconciliation in the dispatched gap remains queued; work
acceptance changes only attempt status. Leaving awaiting work discards its
command, and each new dispatched attempt starts with none. The independent
field and its manual clearing assignments are deleted.

Running-work precedence, sticky unregister, invariant-failure priority,
cancellation counts, declaration lifetimes, paired generation allocation and
provider effect ordering remain unchanged. Native attempt retirement still
records unacknowledged work; it does not simulate IC rollback. The existing
PocketIC evidence remains necessary for rollback and recovery guarantees.

## Successful ordinary transitions determine their effects

After successful ordinary scheduling or completion, the registry previously
read the resulting registration and handled contradictory states as recoverable
`DirectiveNotAllowed` failures. The control transition has already installed
the supplied deadline, or stopped when no successor was selected. No suspension,
callback or provider call intervenes before constructing its effect.

The registry now builds each arm from that selected deadline and the newly
allocated generation. Completion selects its effect from the same optional
successor it passed to control. The two impossible recovery branches are
deleted. Public input validation, directive validation, exact callback authority,
checked allocation failures, provider installation and effect confirmation
remain at their existing boundaries.

All three changes affect private volatile implementation. No public API or
snapshot shape changes, stored-data transition, generated artifact or downstream
adapter change is required. This is a patch release with no compatibility path.

## Focused verification

The maintainer's lint run reported `single_match_else` in ordinary completion's
optional successor selection. That branch now uses `if let` with the same arm,
stop, cancellation and removal behavior. The lint gate has not been rerun by
the automated contributor.

Existing control fixtures cover scheduling and completion allocation, stopping,
cancellation and exhausted-generation atomicity. Ordinary registry transition,
pending-command, terminal-lifetime and provider-failure fixtures remain.
Watchdog checked-failure fixtures retain their public inactive reason, selected
callback cleanup and generation atomicity checks; assertions about the removed
independent pending field are deleted.

The native unacknowledged-attempt fixture now queues reconciliation before
discarding dispatched work. It checks that successor work stops normally,
rather than inheriting the retired attempt's requested deadline, and clears its
provider handles. The existing dispatched-reconciliation fixture checks that
the command survives work acceptance and governs that attempt's completion.
Running-command precedence and invariant-failure fixtures remain.

Tests, builds, lint gates and deployment validation remain maintainer-owned;
none were executed during preparation. No new runtime, recovery or performance
result is claimed. Downstream work remains deferred.

Changed Rust is formatted. Diff whitespace, current release-truth and read-only
0.10.5-to-0.10.6 note/handoff checks passed. The public crate facade, Cargo
manifests, both lockfiles and Git index are unchanged. No version bump or Git
release operation was run during preparation.
