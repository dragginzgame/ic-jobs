# 0.10.11 Watchdog dispatch-failure coverage

Status: released 0.10.11.

## Watchdog dispatch-failure fixture

The existing native dispatch-failure fixture covered failure while binding the
queued work handle and while confirming the complete effect, only for retained
declarations. It now covers all three stages: binding the first successor handle,
binding the work handle after the successor is installed, and confirming the
effect after both handles are installed. Each stage runs with retained and
remove-on-stop declarations, using the existing fault injection machinery.

Every case checks that no provider timer or queued work remains and that consumer
work is never invoked. Retained declarations stay inactive with
`ProviderBindingFailed`: the initial arm is the only confirmed wakeup, and no
dispatch, work start or completion is falsely counted. Remove-on-stop declarations
expire their claim and release their identity. A replacement declaration can arm
that identity while the old claim still returns `RegistrationExpired`; unregistering
the replacement clears its handle.

No production implementation, public API, dependency or generated artifact changes.
Public-control retirement and Watchdog work-message rollback remain separate.
This native fixture extension does not establish new IC rollback or provider
heap-bound evidence. The maintainer has selected 0.10.11 for this test-only work.
Publication still creates a new package identity for exact-pinned consumers,
despite unchanged production behavior. The complete deployment release gate
remains maintainer-owned.
