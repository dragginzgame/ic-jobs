# 0.9.5 timer control and release handoff

Status: released 0.9.5.

## Private provider effects

The registry's policy control state owns absolute deadlines. Provider binding and
confirmation consume resolved delays, callback tokens and arm kind; the absolute
deadline copies in `RegistryEffect` had no production reader. Both copies are
removed. Existing pure registry fixtures now read deadlines from authoritative
snapshots and continue checking provider delays and callback generations. Runtime
malformed-token fixtures retain role and claim checks without the removed fields.

The public API and snapshot shape are unchanged. Relative scheduling metadata,
overdue zero-delay arms, effect confirmation, partial-binding cleanup, declaration
lifetimes and Watchdog scheduler/work ordering keep their existing owners.

## Ordinary cancellation

Ordinary control cancellation now returns checked success or a typed error, as
completion already does. It invalidates scheduled generations and leaves inactive
or running control unchanged. The registry observes the pre-cancellation state to
decide provider cleanup, declaration lifetime, cancellation counting and pending
commands. Scheduling actions no longer include `Clear`; cancellation cannot return
an arm action. The corresponding impossible fallback branches are removed.

Existing control fixtures observe resulting registration and generations rather
than cancellation actions. They also check that repeated cancellation does not
allocate a generation and that exhausted scheduled cancellation fails without
mutating control. The maintained registry failure/lifetime matrix and runtime
handle-cleanup/idempotence fixtures cover the surrounding boundaries. Generation
checks, sticky unregistration and nested command arbitration remain unchanged.

## Release handoff

Cargo remains the version authority. The handoff keeps one workspace-version
projection; the redundant latest-release marker, mutation and validation branches,
and obsolete marker fixtures are deleted together. Existing release fixtures
continue rejecting missing, duplicate, conflicting and wrong workspace markers.
Release-note status, dated changelog, README projections and rollback checks remain.

The sentence-specific README release prohibition is deleted. The existing positive
release fixture includes editorial release prose while the structural negative
cases continue checking the API line and exact dependency pin. Free-form prose
cannot block release finalization. Preparation evidence is explicitly historical;
current follow-up no longer repeats completed release instructions.

## Scope and verification

These are private crate and repository-tooling simplifications suitable for a
patch release. No compatibility path or replacement framework is introduced.
Downstream work is deferred at the maintainer's request.

The released baseline is the maintainer-reported live 0.9.4 and its matching
release artifacts, with successful inspected hosted main/MSRV and tag jobs at
`40b36d8fdebc7dc7b2730fdea9237c7027e3113f`. That evidence does not qualify new
changes or downstream deployments.

The existing control, registry, runtime, release-truth, version-preparation and
release-commit fixtures are the focused verification subjects. Tests, builds, lint
gates and release commands were not run during preparation. Formatting, diff
inspection and cheap read-only release-metadata checks are recorded in the handoff.
The maintainer owns deployment validation, version mutation, Git staging, commits,
tags and pushes.
