# 0.4.1 private-runtime cleanup

Status: released 0.4.1.

## Implemented scope

- Correct fresh `RemoveWhenStopped` cancellation for Once, after-completion,
  and Watchdog registrations. Cancellation now removes the declaration and
  expires its claim even before the first schedule.
- Resolve explicit ordinary schedules through one private constructor instead
  of duplicating deadline, requested-delay, and scheduling-mode projection.
- Match recurring policy directly instead of routing ordinary versus Watchdog
  behavior through boolean intermediate state.
- Carry Once ensure, after-completion ensure, and authoritative reconciliation
  as a closed ordinary request kind instead of combining a generic request
  value with a separate `require_once` boolean and wrapper.
- Install and verify retained lifecycle registration slots through one generic
  private seam shared by all three policies.
- Derive immediate Watchdog cancellation accounting and transient removal from
  canonical state rather than returning a second boolean from the private
  transition helper.
- Bind ordinary and Watchdog provider operations from the complete canonical
  effect instead of passing duplicate tokens and delays to private helpers.
- Validate effect shape before cleanup, provider calls, or counter
  confirmation. Watchdog successor and work tokens must carry the expected
  roles and the same exact identity plus claim generation.
- Reuse one entry-local exact-claim predicate for callback acceptance,
  measurement, provider installation, running-context validation, and
  provider-handle consumption.
- Carry one initial/replacement arm kind from ordinary control through the
  registry effect instead of splitting and rejoining duplicate variants.
  Encode the non-empty callback set to clear as a second closed private value.
  Effects can no longer represent "clear nothing," and Watchdog scheduler
  replacement is rejected at the common shape boundary.
- Share one detached-handle transition path between cancellation and explicit
  unregistration, removing another pair of restore/retire branches.
- Remove compatibility-only exhaustiveness markers from private control
  errors; no legacy error reader or forwarding path remains.
- Correct public comments where scheduling demand can be a running attempt's
  pending successor and where cancel/unregister cannot interrupt active work.
- Preserve the single bounded registry, exact provider-handle ownership, and
  two-message Watchdog protocol.

No compatibility shim, alternate registry, provider re-export, or fallback
path is in scope.

## Evidence

Focused pure-registry and live-runtime tests prove that fresh transient
cancellation removes all three policies, owns no provider handle, releases
bounded capacity, and makes each sole-owner registration claim expire.

Two negative effect-boundary tests mix tokens from independent Watchdog claims.
The runtime rejects the malformed pair before arming a provider callback, and
the registry rejects it before confirming arm or dispatch counters. Invalid
work-role and Watchdog-replacement arm effects are rejected at the same
boundary. Clear effects have no empty selection to test.

An identity-reuse regression retains an old callback token, removes its
transient declaration, registers a replacement with the same identity and
callback generation, then proves the stale token cannot detach the new
provider handle. The replacement remains observable, cancellable, and the
sole owner of that handle.

The normal CI gate passes with 83 native tests, warning-denied Clippy and
rustdoc, Wasm compilation, and offline package verification. Rust 1.88 checks
the complete workspace and every nested runtime and size-probe configuration.
The dependency tree has no duplicates, release impact is correctly classified
as `crate`, both non-mutating 0.4.1 finalizer checks pass, and diff whitespace
validation passes.

PocketIC is not repeated because fresh inactive cancellation owns no provider
handle, malformed effects are rejected before provider calls, and the stale-
token fix only tightens which exact claim may detach an existing handle. No
valid provider operation, callback dispatch, or Watchdog message transition
changed. The maintainer-owned version bump retains the full release gate.
