# 0.10.10 Watchdog completion removal

Status: released 0.10.10.

## One removal decision after Watchdog completion

Watchdog completion previously returned a declaration-removal flag from each
decision branch. Normal stop repeated the lifetime and pending-unregister rule,
while failed successor replacement separately checked terminal failure and
remove-on-stop lifetime. Continuation branches each supplied a constant false.

Each branch now produces only its transition. Completion decides removal once
after the branch has selected its final state: an inactive declaration is removed
when its lifetime is remove-on-stop or an unregister command was pending.
The branch-local removal decisions and separate unregister flag are deleted.
No new policy layer or state model is introduced.

Keeping or successfully replacing a successor still leaves the declaration
scheduled, including a remove-on-stop declaration that continues. Failed checked
replacement still stops with generation exhaustion and clears the previous
wakeup. Retained terminal declarations remain observable. Pending unregister
still forces stop and removal; explicit invariant failure still wins terminal
classification over cancellation. Completion accounting and scheduling metadata
retain their existing order and semantics.

Exact work-token validation, detached provider-handle finalization and unexpected
Watchdog callback failure rollback remain unchanged. This is a private
implementation simplification suitable for a patch release, with no public API,
snapshot shape, persistence, dependency, generated artifact or downstream change.

## Focused verification

The existing Watchdog terminal-failure matrix now accepts work and exhausts the
scheduler generation before both immediate and exact-deadline completion
replacement. For both declaration lifetimes it checks the typed terminal failure
and selected wakeup cleanup. Retained declarations report the control-failure
reason with completion accounting and no successful cancellation; transient
declarations disappear, expire their claim and allow a new declaration identity.

A small continuation fixture checks that remove-on-stop declarations survive
keeping and replacing a successor. Keeping cadence, keeping an overdue immediate
successor and keeping an equal exact deadline all work with an exhausted scheduler
generation counter; an actual replacement advances its generation and deadline.

Existing successor-retention, pending-command arbitration, unregister, invariant
failure and runtime provider-cleanup fixtures retain their behavioral coverage.
The expanded failure matrix has a scoped length-lint expectation so its shared
setup and lifetime assertions remain together.

Tests, builds, lint gates and deployment validation remain maintainer-owned and
have not been run during preparation. No new PocketIC, recovery or performance
result is claimed. Changed Rust is formatted, and diff whitespace checks passed.
Read-only current release-truth and 0.10.9-to-0.10.10 note/handoff checks passed.
Cargo versions, lockfiles and Git release operations remain maintainer-owned.
The changelog section stays undated until release execution.
