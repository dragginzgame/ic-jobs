# 0.10.20 validation and outcome ownership

Status: released 0.10.20.

## Checks at their operation boundaries

`reconcile_registration` directly verifies the supplied identity, exact
registration claim, policy, cadence and retained declaration lifetime before
returning the capability to its Once, AfterCompletion or Watchdog lifecycle
caller. The single-caller `verify_declaration` helper is deleted. Fresh
registration still happens only when the consumer's slot is empty; an existing
slot keeps its original callback. Identity conflicts are rejected before the
registry borrow, and registry claim errors keep their existing classification.

`apply_claim_transition` directly verifies an optional callback token's exact
running-work authority before detaching provider handles or invoking the registry
operation. The single-caller `validate_context` helper is deleted. Retained
registration calls still supply no context token; context calls still require
the matching role, claim, generation and running state. A rejected context cannot
clear or replace a successor's handles.

All policy control callers still converge on the same transition operation and
detached-claim finalizer. These edits move checks into their sole callers; they
do not remove trust-boundary checks, change borrow scope or error ordering, or
merge callback recovery with synchronous control recovery. Public API, snapshots,
provider effects and lifecycle reconstruction behavior are unchanged.

Ordinary directive resolution and public directive-snapshot conversion were
also inspected. The snapshot conversion retains its independently checked public
boundary; no observation value gains runtime mutation authority.

## One recorded terminal event

`TimerOutcomeSnapshot` stores one optional private `RecordedOutcome` instead of
independently optional latest classification and work-count fields. A completion
event contains its existing `TimerCompletion`, which owns both values; an
unacknowledged event carries no work count. `last_outcome()` and
`last_work_count()` project their existing public values from that event.

Both existing writers always updated the old fields together. Consolidating the
fields removes that synchronization requirement: a completion without its work
count, or an unacknowledged attempt with a completion count, is no longer a
representable stored state. Empty observations still return `None`; a zero-work
completion still returns `Some(0)`; interruption still clears the latest count;
and a later completion still replaces the unacknowledged observation.

Success, failure and unacknowledged timestamps and the expected-failure streak
remain independent history. They cannot be derived from the latest event alone.
The public `TimerLastOutcome` enum and getter signatures are unchanged. The
aggregate's private Rust layout changes; there is no persisted codec, public
layout guarantee, wire change or generated binding change. No memory or
performance savings were measured.

## Verification and delivery scope

Existing focused native subjects include lifecycle reconstruction and declaration
conflicts, retained Once and Watchdog context expiration, stale identity reuse,
nested and suspended control, and restoration after transition errors. Their
behavior assertions are retained; no test mirrors the removed helper names or
their placement. Native fixtures do not establish IC rollback or provider heap
bounds.

The new native fixture
`latest_outcome_keeps_work_count_and_independent_history_coherent` checks public
observations through empty, successful zero-work, no-work, retryable failure,
unacknowledged, invariant failure and later successful events. It checks that
interruption clears only the latest count while retaining timestamps and the
expected-failure streak, and that subsequent completion restores the appropriate
count and updates only the applicable history. Existing registry Watchdog
retirement and ordinary/Watchdog lifetime fixtures remain relevant; the
consumer-shaped snapshot projection fixture retains its existing public values.

Changed Rust was formatted. Diff whitespace, staged-changelog validation,
release-note preflight and current release-truth checks passed.

Tests, builds, lint gates and deployment validation remain maintainer-owned and
were not run. This private behavior-preserving cleanup fits 0.10.20. Cargo
versions, both lockfiles, dependencies and generated artifacts are unchanged.
The changelog heading remains undated; version mutation and all Git/release
execution remain maintainer-owned. Downstream work remains deferred.
