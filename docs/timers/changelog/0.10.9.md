# 0.10.9 ordinary callback finalization

Status: released 0.10.9.

## One ordinary completion owner

Ordinary dispatch previously completed normal callback results inline and used
`fail_ordinary_dispatch` to repeat registry completion and effect finalization
for an unavailable callback borrow. Both now call `finish_ordinary_callback`,
which completes the exact running token at current platform time and finalizes
its registry transition. The separate failure-completion implementation is deleted.
Unexpected completion errors use the shared ordinary-completion trap diagnostic.

Callback-borrow failure still supplies invariant failure with zero completed work
and a stop directive, without invoking the callback or recording a work measurement.
Normal completion still records measurements after effect finalization. Registry
arbitration, lifetime removal and provider cleanup retain their existing contracts.
Watchdog completion and its detached-handle rollback path remain separate.

## Remove an unreachable dispatch branch

Successful ordinary acceptance establishes the token's ordinary role, declaration
claim, generation and running state. There is no asynchronous boundary, consumer
callback or provider operation between that acceptance and callback lookup. The
lookup cannot therefore encounter a different policy on this path.

Dispatch no longer treats lookup ownership mismatch as a recoverable callback
failure. Unexpected lookup errors trap consistently. The registry's callback
lookup retains policy validation for independently supplied work tokens; this
change does not remove a trust-boundary check.

This is a private implementation simplification suitable for a patch release.
Public API and snapshot shapes, persisted formats, dependencies and generated
artifacts are unchanged. No compatibility path or downstream update is required.

## Focused verification

A native fixture retains a mutable callback borrow while a scheduled Once wakeup
dispatches. It checks that the callback is not invoked, no timer remains, retained
declarations report invariant failure with one completed attempt and no work
measurement, and remove-on-stop declarations expire. The fixture covers both
declaration lifetimes without adding a production test hook.

Existing native fixtures cover normal completion measurements, recurring arming,
suspended-work arbitration and stale-token rejection. Tests, builds, lint gates
and deployment validation remain maintainer-owned and have not been run during
preparation. No new PocketIC, recovery or performance result is claimed.

Changed Rust is formatted, and diff whitespace checks passed. Read-only current
release-truth and 0.10.8-to-0.10.9 note/handoff checks passed.

Cargo versions, lockfiles and Git release operations remain maintainer-owned.
The changelog section stays undated until the maintainer runs the release helper.
