# 0.10.21 canonical claim lookup and rejection coverage

Status: released 0.10.21.

## Canonical mutable claim lookup

`TimerRegistry::entry_by_token_mut` delegates to `entry_mut` using the claim already
contained in the callback token. The callback-specific lookup no longer repeats
map lookup and claim-generation comparison. It retains the callback boundary's
error translation: both missing and superseded claims return `StaleCallback`.

Affected callers are provider installation and confirmation of ordinary arms,
Watchdog scheduler arms and Watchdog dispatch. They retain their independent
policy, role, state, callback-generation, handle-slot and effect-shape checks.
Running-work authorization, handle consumption and late measurement accounting
keep their distinct checks and failure contracts. Handle restoration, provider
cleanup and Watchdog rollback behavior are unchanged.

`provider_installation_and_confirmation_reject_removed_or_reused_claims` covers
both an absent entry and a replacement with the same identity and a different
claim generation. Provider installation must return `StaleCallback` alongside
the rejected handle, leaving it available for caller cleanup. Confirmation must
return `StaleCallback` without changing inventory or accounting. The replacement
is scheduled with the same callback-generation value as the original, so callback
generation alone cannot satisfy claim authority.

## Public reconciliation boundaries

Four focused native fixtures exercise the public lifecycle entry points:

- `once_reconciliation_rejects_identity_mismatch_without_disturbing_live_work`
  passes a different identity alongside an existing scheduled Once capability.
  It expects `ReconciliationConflict`, retains the original consumer slot and
  armed wakeup, and executes the original callback at its original deadline.
- `after_completion_reconciliation_rejects_transient_lifetime_without_cancelling_work`
  supplies a live remove-on-stop declaration to retained lifecycle reconciliation.
  It expects `ReconciliationConflict` and retains the scheduled callback. Its
  eventual normal stop still removes the transient declaration.
- `after_completion_reconciliation_rejects_cadence_mismatch_without_disturbing_live_work`
  submits a different cadence for an armed retained declaration with matching
  identity and lifetime. It expects `ReconciliationConflict`, preserves the
  inventory and armed wakeup, and executes the original callback at the original
  deadline, with no work before that deadline. This case is independent of the
  transient-lifetime rejection so neither check can mask the other's absence.
- `watchdog_reconciliation_rejects_reused_identity_claim_without_clearing_replacement`
  expires a scheduled transient declaration through public cancellation,
  registers and schedules a replacement under the same identity, then submits the
  old slot to reconciliation. It expects `RegistrationExpired`; the old slot
  remains expired and the replacement's scheduler and work still execute its
  installed callback.

Each rejected request asks for inactivity, so bypassing validation would cancel
live work. Each compares the complete inventory before and after rejection,
checks native provider timer count and exact-claim armed-wakeup observations,
then executes the live callback. A supplied replacement callback reports a
different result; callback counters establish that the installed callback is
retained. The expired Watchdog callback has a separate counter and must not run.

These cases exercise the shared identity, declaration-lifetime, cadence and claim
checks through three public callers. They are not a matrix of every rejection
against every policy. The existing Watchdog cadence-conflict and successful
reconstruction fixtures remain maintained.

## Failed fresh reconstruction

The existing duplicate-registration fixture is extended and renamed to
`duplicate_registration_and_reconstruction_preserve_live_work_and_release_capacity`.
It now arms the original transient declaration before testing both direct duplicate
registration and lifecycle reconstruction from an empty consumer slot. The latter
requests inactivity and returns `Register(IdentityAlreadyRegistered)` with the
occupied identity. The slot remains empty; both rejections preserve the complete
inventory and original armed wakeup. The installed callback subsequently executes
at its original deadline, and its normal stop releases the declaration.

This covers failure during claim creation, before an empty lifecycle slot receives
authority, separately from validation of an already-populated slot. The original
direct-registration negative case and remove-on-stop behavior remain in the same
fixture; no additional test harness or production path is introduced.

## Verification and delivery scope

This private, behavior-preserving cleanup and its tests affect published crate
source. Public API, snapshot shapes, dependencies and generated artifacts are
unchanged. No runtime bug fix, new recovery guarantee or performance change is
claimed. The cleanup fits the 0.10 patch line.

The four new lifecycle rejection fixtures, the extended duplicate-registration
fixture and the provider claim-rejection fixture above are focused maintainer
verification subjects. Existing provider role/detachment and Watchdog dispatch
confirmation fixtures remain relevant to the lookup cleanup. Native provider
observations do not establish IC rollback, delivery guarantees or provider heap
bounds. Tests, builds, lint gates and deployment validation remain maintainer-owned
and were not run.

Changed Rust was formatted. Diff whitespace, staged-changelog validation,
release-note preflight and current release-truth checks passed.

Cargo versions and both lockfiles remain unchanged. The changelog heading is
undated. Version mutation and all Git/release execution remain maintainer-owned;
downstream work remains deferred.
