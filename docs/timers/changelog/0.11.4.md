# 0.11.4 request observation ownership

Status: released 0.11.4.

## One Watchdog coalescing update

`TimerRegistry::ensure_watchdog` previously recorded coalescing independently in
scheduled, dispatched and running branches. The branches still select their
different control behavior, but no longer each own an observation update. The
common request exit records coalescing only for a no-effect transition without a
control failure.

This condition preserves an important distinction: an initial arm at maximum
generation also returns no provider effect, but its terminal failure is not
coalescing. Successful initial and replacement arms still emit `ArmWakeup`; failed
replacements emit cleanup with a typed failure. Deadline errors still return
before request accounting. Accepted requests still record their requested delay
and request count, including failed allocation. Pending-command selection, lazy
cadence deadline calculation, mode retention and declaration lifetimes are
unchanged. All updates remain inside the same registry borrow before provider
effects are applied.

## One ordinary request mode update

`TimerRegistry::request_ordinary` previously committed the mode for exact
reconciliation and then again for its successful arm. One condition now owns
both cases: commit the requested mode if an arm was selected or the request is
exact reconciliation. Allocation failures still return before that update.

Ordinary and Watchdog requests intentionally keep different observation contracts.
An equal-deadline ordinary reconciliation updates mode to the authoritative
request, and running reconciliation records its pending request's mode. An
ordinary coalesced ensure preserves the existing mode. Watchdog coalesced and
pending requests preserve their armed mode until completion. This change removes
duplicate writes within those owners without introducing a shared policy layer or
changing either contract.

## Restore the README version projection

The released README rewrite replaced its structured API-line field with a prose
sentence. `readme-version.sh` owns automatic projection into one structured field
and the exact dependency example; its check therefore failed before version
preparation. The technical overview now carries that single API-line field again,
and the prose no longer repeats the version. The helper and its maintained fixture
format remain unchanged. This repository-only repair accompanies the runtime work;
it adds no version selector or interpreted-prose release gate.

## Scope and focused verification

These are private, behavior-preserving changes suitable for a patch. Public APIs,
snapshot shapes, callback generations, dependencies and persisted formats are
unchanged. No generated artifact, compatibility path or downstream adapter needs
updating. Downstream work remains deferred.

Existing fixtures were extended:

- `watchdog_requests_preserve_dispatch_authority_until_completion_replaces_the_pair`
  now requires five total requests and three coalesced requests after cadence,
  immediate and exact requests during either dispatched or running work.
- `watchdog_terminal_failures_respect_declaration_lifetime` requires no coalesced
  events in its retained failure subjects, including an initial exhausted arm
  with no provider effect. Both transient removal and retained accounting remain.
- `ordinary_reconciliation_is_authoritative_and_registry_pending_is_ordered`
  includes an equal relative request after an absolute arm. It requires unchanged
  runtime state, relative mode and requested delay, then accepts the existing
  callback token and exercises the original running-command sequence.

Existing scheduled/overdue Watchdog coalescing, ordinary recurring ensures at
maximum time, exact reconciliation, pending precedence and provider-binding
fixtures remain applicable. No new test suite or source-name assertion is added.

Tests, builds, lint gates and deployment validation remain maintainer-owned and
have not been run. Changed Rust was formatted. Diff whitespace, prepared release
metadata, current release truth and locked offline dependency metadata checks
passed, including the README projection check after its structured field was
restored. These checks do not establish runtime or IC recovery results.
Cargo versions and lockfiles remain unchanged. The changelog section is undated
and `Unreleased` is empty; version bumps and all Git/release execution remain
maintainer-owned.
