# 0.8.3 release workflow

Status: released 0.8.3.

## Changes

- Combined release targets always run the requested version bump after the
  complete deployment gate. `make release-patch` advances 0.8.2 to 0.8.3;
  it does not reuse an untagged version.
- Release-impact classification uses the most recent reachable canonical
  version tag for the pending subject. The absent `v0.8.2` tag therefore does
  not block the next bump; the existing `v0.8.1` tag is the baseline. Explicit
  missing bases, missing release history and Git failures remain errors.
- Release commit creation validates the metadata and both lockfiles and
  rejects unstaged or untracked changes before committing or tagging.
- Automated contributors prepare only changelog sections and release-line
  notes. Version mutation, tests, staging, commits, tags, pushes and publication
  remain user-owned.

This is repository-only release tooling and documentation work. The maintainer
explicitly selected 0.8.3; no runtime, public API or dependency change is claimed.
The completed bump set Cargo and both lockfiles to 0.8.3 and dated its changelog.

## Validation

Automated contributors did not run tests, build/lint gates or release commands
for these workflow changes. The maintainer subsequently reported the release
live; deployment validation remains user-owned. Updated regression fixtures cover
an untagged workspace version, explicit missing bases, failed Git discovery,
and the matching bump command in each combined release target.
