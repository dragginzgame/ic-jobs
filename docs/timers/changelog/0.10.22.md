# 0.10.22 lookup, detachment and terminal control ownership

Status: released 0.10.22.

## Canonical lookup with distinct failure contracts

Late callback measurement accounting and provider-handle consumption use
`TimerRegistry::entry_mut` with the claim contained in the callback token. These
paths no longer repeat identity lookup and claim-generation comparison. Missing
or superseded claims remain successful no-ops: a removed declaration has nothing
left to observe or consume, and an old callback must not affect a replacement.

Measurement routing retains its policy/role validation. Handle consumption
retains its policy/role slot selection and exact provider callback-generation
comparison. This cleanup does not merge either path with running-work
authorization, provider installation or effect confirmation, whose failure and
state checks remain distinct. Public API, snapshots, ordering, declaration
lifetime, provider effects and recovery behavior are unchanged.

## Entry-owned provider-handle pairs

Watchdog dispatch failure cleanup obtains the entry's paired provider capabilities
through `TimerRegistry::take_provider_handles`, which delegates to the existing
entry detachment operation. The runtime no longer selects the same identity twice
and assembles its own pair. `ProviderHandles::from_parts` is deleted; the restoration
fixture uses the registry operation too.

The entry remains the owner of role-stamped handle detachment. Wakeup detachment
still precedes work detachment; both happen under one registry borrow, and platform
clearing still happens after that borrow is released. An existing entry without
handles and a missing identity both return an empty pair. Unavailable or busy
runtime access still returns the original typed error without losing handles.
Claim-authorized detachment and individual slot selection retain their distinct
requirements; callers that clear a selected callback do not detach unrelated work.

The provider-cleanup fixture adds harmless empty-entry and missing-entry cleanup
after its existing borrow-failure and subsequent successful cleanup assertions.
The restoration fixture still verifies that failure to restore the first handle
clears it, restores the second handle, and returns the first error. It now obtains
that remaining handle through the paired registry operation for cleanup.

## Typed ordinary terminal control

`terminal_ordinary` now accepts `&mut TimerControl` instead of an entire registry
entry. Its only callers, ordinary scheduling requests and ordinary cancellation,
already select and validate the ordinary payload before reaching checked control
failure. Passing that control directly removes a repeated policy match and an
unreachable fallback that returned a terminal transition without stopping control.

The helper still sets the same inactive control-failure reason and emits wakeup
cleanup only when a scheduled callback must be cleared. The callers still own
transient removal after failure. Policy validation remains at the request boundary;
completion accounting and Watchdog termination retain their separate paths.

## Verification and delivery scope

This is a private, behavior-preserving production cleanup suitable for the 0.10
patch line. Dependencies, generated artifacts, Cargo versions and both lockfiles
remain unchanged. No new performance, provider-heap or IC rollback claim is made.

Tests, builds, lint gates and deployment validation remain maintainer-owned and
were not run. Existing focused subjects cover the changed boundaries:

- `stale_reused_identity_callback_cannot_change_handles_or_measurements` directly
  records late measurements after removal and identity reuse, consumes an old
  token against the replacement, verifies its armed handle survives, executes
  valid replacement work, and rejects a later stale measurement overwrite.
- `provider_roles_reject_same_claim_mismatches_and_survive_detachment` preserves
  owned handles after wrong-role and wrong-callback-generation consumption,
  including Watchdog scheduler and work handles.
- `measurement_routing_rejects_a_policy_role_mismatch` retains the typed policy
  error and unchanged measurement observations for a current claim.
- `provider_cleanup_borrow_failure_is_returned_instead_of_discarded` covers typed
  borrow failure without handle loss and successful cleanup of empty/missing entries.
- `provider_restoration_drains_all_detached_handles_after_first_failure` covers
  draining both handles and paired detachment of the restored work handle.
- `watchdog_failed_dispatch_clears_handles_without_confirming_work` exercises
  successor binding, work binding and effect confirmation failures for both
  declaration lifetimes, retaining cleanup and accounting assertions.
- `ordinary_terminal_failures_respect_declaration_lifetime` covers initial arm,
  replacement, cancellation and completion exhaustion for Once and AfterCompletion
  under both lifetimes, retaining terminal-state and completion assertions. It
  exercises both callers of the narrowed terminal-control helper.

Existing fixtures are extended; no new test harness or test fixture is added.
Changed Rust is formatted; diff whitespace, staged-changelog validation,
release-note preflight and current release-truth checks passed.

The changelog is undated with an empty `Unreleased` section. Version mutation,
Git staging, commits, tags, pushes and release execution remain maintainer-owned.
Downstream work remains deferred.
