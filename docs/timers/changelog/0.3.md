# 0.3 production runtime slice

Status: Patches 1–6 complete; downstream review remains

## Objective

Implement the smallest bounded live timer registry and runtime that can prove
IcyDB's startup recovery watchdog contract while remaining the one shared timer
authority for Canic and application timers.

The non-negotiable boundary is that a small one-shot scheduler message commits
the next watchdog successor before a separate work message invokes fallible
consumer code.

## Planned landing patches

1. Freeze current evidence, API decisions, provider behavior, Rust 1.88
   feasibility, and measurement baselines.
2. Add coherent policy-specific values and the pure bounded registry.
3. Bind linear platform handles and implement `Once` and `AfterCompletion`.
4. Implement the one-shot two-message `Watchdog` protocol.
5. Add lifecycle reconstruction, live observations, measurements, and the
   IcyDB-shaped fixture.
6. Close the complete PocketIC recovery/isolation matrix and report Wasm,
   instruction, MSRV, and complexity results.

See the full [0.3 production runtime design](../design/0.3-production-timer-runtime.md).

## Patch 1: frozen contract and baseline

Disposition: complete.

The current 0.2 implementation, IcyDB watchdog, Canic timer/lifecycle surface,
and pinned provider source were inventoried. The resulting
[runtime contract](../design/0.3-patch-1-contract.md) freezes:

- 64 canonical registry entries and at most two provider handles per watchdog;
- private linear provider ownership and a single global registry;
- separate async ordinary and synchronous watchdog callback APIs;
- retained versus remove-when-stopped declaration lifetime;
- validated positive cadence and the policy/directive matrix;
- policy-specific ordinary/watchdog states;
- committed dispatch and truthful unacknowledged-attempt semantics;
- split wake-up/work arms and scheduler/work instruction measurements;
- system-derived runtime epochs and a synchronous composable lifecycle seam;
- exact provider source hashes and behavior dependencies; and
- comparable raw-Wasm and instruction measurement subjects for later patches.

Native and Wasm compilation of the current source and dependency graph pass on
Rust 1.88.0. The declared MSRV is lowered accordingly while the development
toolchain remains unchanged.

## Patch 2: coherent pure registry

Disposition: complete.

The pre-1.0 API is hard-cut to the frozen value contract. Positive recurring
cadence is validated once, after-completion recurrence uses that configured
cadence, snapshots have closed policy-specific states and private fields,
unacknowledged watchdog dispatch replaces interruption claims, elapsed IC time
is omitted, and counters/instruction aggregates are split by callback role.

The internal pure registry now provides:

- exactly 64 deterministic `BTreeMap` entries;
- unique opaque claim generations and typed duplicate/capacity failures;
- retained and remove-when-stopped declaration lifetimes;
- claim-consuming unregistration, including deferred removal during work;
- `Once`, `AfterCompletion`, and watchdog scheduler/work state transitions;
- checked cadence, deadline, request, and generation arithmetic;
- nested ensure/cancel arbitration and stale generation rejection;
- coherent registry-only snapshot construction; and
- effect-application confirmation so actual-arm counters never count a merely
  proposed provider effect.

Forty-one native tests cover the owning pure behavior. Strict Clippy, rustdoc,
and Rust 1.88 native/Wasm checks pass. No provider handle is stored, no
callback is executed, and no watchdog commit-boundary or recovery guarantee is
claimed.

## Patch 3: live ordinary runtime

Disposition: complete.

One thread-local canister runtime now owns the canonical registry, ordinary
callbacks, and every live ordinary provider handle. A synchronous idempotent
initialization seam derives its epoch from IC system facts but exports no
lifecycle hook. Opaque non-clone registration claims expose exact-policy
ensure, cancel, and consuming unregister operations. `TimerContext` permits
defined nested ensure/cancel requests while consumer futures execute without a
registry borrow.

`Once` and `AfterCompletion` effects now arm `ic-cdk-timers` one-shots through
the private platform boundary. Replacement and cancellation consume and clear
the actual handle, callback generations reject stale dispatch, and actual-arm
counters advance only after handle ownership is installed. After-completion
recurrence computes its successor from the callback's real completion time.

Forty-seven focused tests pass on the development toolchain and Rust 1.88.0.
Strict Clippy, rustdoc, Rust 1.88 native/Wasm checks, and offline package
verification pass. The provider harness is native-only evidence of ownership
and dispatch; it is not evidence of IC message commit behavior. Watchdog
effects remain deliberately unbound and unavailable from the public API.

## Patch 4: committed-successor watchdog

Disposition: complete.

The public runtime now registers synchronous `Watchdog` work. Its bounded
scheduler callback generation-checks, retires any older dispatched attempt,
computes one successor from current dispatch time, arms that successor first,
queues one zero-delay work callback second, confirms both exact handles in the
canonical entry, and returns without reading or invoking consumer work. The
later work callback generation-checks, drops the registry borrow, invokes
synchronous work, and either retains or clears the committed successor.

Each watchdog entry owns at most two private linear provider handles. Focused
native tests cover scheduler/work separation, pre-arm visibility during work,
terminal clearing, remove-on-stop, nested cancel/ensure, unacknowledged
takeover, and large overdue-time coalescing. The runtime suite now has 53 tests.

An isolated Rust 1.88 PocketIC 15 probe supplies the first real-canister
boundary evidence: explicit work trap rolls the work message back, the
previously committed successor later retires that dispatch as unacknowledged,
and subsequent work completes. It also confirms that an external caller is
rejected by `<ic-cdk internal> timer_executor`. The compiler-release probe
subject used for this evidence (without external `wasm-opt`) is 299,629 raw
bytes with SHA-256
`15578495ab5aba0080ecf19b86a7c260b16694e6b4c3af73111dfb11a6327e51`.
This is not a cohort delta and is not the final size report.

## Patch 5: reconstruction, measurements, and IcyDB-shaped fixture

Disposition: complete.

Synchronous reconciliation helpers now combine a caller-owned volatile
registration slot, exact identity/policy/lifetime verification, and an
explicit scheduled/inactive desired state. A fresh heap installs callback
authority before ensuring a wake-up; repeated calls reuse the exact claim and
cannot replace its callback. Consumers still derive desired state from their
own durable authority, and the library persists nothing or exports no
lifecycle hook.

The runtime now samples IC call-context instruction counter type 1 around
accepted scheduler and work paths. Only normally completed messages commit
samples; trapped work has no synthetic zero. Internal provider-binding failure
terminates the registration with a truthful typed control failure and clears
any owned capabilities rather than silently discarding a callback error.

The 56-test native suite includes an IcyDB-shaped fixture with one fixed
watchdog identity, consumer-supplied Ready/Recovering/terminal-failure state,
synchronous one-page work, terminal stop, retryable continuation, idempotent
reconstruction, and returned-error/commit-guard re-enablement. It copies no
database authority or public executor.

The PocketIC probe now upgrades while scheduled. Its probe-owned durable bit
requests reconstruction in `post_upgrade`; a downstream-hook observation sees
the newly owned wake-up, epoch counters restart, and later work progresses.
The observed pre-upgrade samples were two scheduler callbacks totaling 41,900
instructions and one normal work callback using 19,998 instructions; the
trapped work committed no sample. The current compiler-release probe is
404,094 raw bytes with SHA-256
`4a2275bba1cbd3b7db4e2ccb45451153425a2776f8ba35ac018281e1172b2a93`.
These are probe-specific absolute values, not the final frozen cohort deltas.

## Patch 6: real-canister closeout

Disposition: complete.

Six focused recovery/inventory tests on PocketIC 15 and Rust 1.88 now cover
explicit trap, actual 40-billion-instruction exhaustion, private executor
ingress, scheduled upgrade reconstruction before downstream observation,
stop/resume, insufficient cycles followed by top-up, terminal and
scheduler/work-gap cancellation, duplicate ensure, two timers due together,
trap isolation, 300-second overdue coalescing, commit-window re-enablement, and
a bounded ordered 64-entry inventory. The full inventory snapshot measured
137,423 instructions.

A separate feature-exclusive probe compares baseline, Once,
after-completion, and Watchdog through identical endpoints and DTOs. After
Binaryen 108 `wasm-opt -Oz`, raw Wasm sizes are 212,248, 253,315, 253,695, and
253,746 bytes respectively. Watchdog is 41,498 bytes over baseline and only 51
bytes over after-completion in this subject. Its no-op scheduler and work paths
measured 19,530 and 19,523 instructions. The extra end-to-end PocketIC balance
charge versus after-completion was 15,364,624 cycles for the deliberate second
provider self-call and scheduler execution.

The exact matrices, artifact hashes, frozen-subject adjustment, complexity
delta, and downstream adoption sketch are in the
[0.3 runtime evidence report](../audits/0.3-runtime-evidence-2026-08-13.md).

No IcyDB or Canic adoption is claimed. Canic's real snapshot/metrics adapter
test and both downstream integration suites remain separate adoption work.

## IcyDB design-review follow-up

Disposition: accepted; no protocol blocker.

The recovery guarantee now explicitly covers trap or instruction exhaustion
in the later consumer-work message, not the small scheduler message whose
normal return establishes the commit boundary. The IcyDB-shaped fixture and
adoption sketch freeze exact mappings for recovery progress, returned
retryable failure, Ready, and durable terminal database failure.

The downstream gate now also requires one resolved `ic-timers` package ID and
a full direct-provider inventory because the provider's 250 outstanding-call
semaphore is canister-wide. Canic must make its currently infallible timer
facade expose typed capacity and 64-byte identity errors. Neither downstream
may claim adoption without its remaining adapter and integration evidence. The
0.3.0 release prerequisite is satisfied.
