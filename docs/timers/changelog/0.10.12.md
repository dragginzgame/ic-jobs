# 0.10.12 generation ownership, provider binding and workspace formatting

Status: released 0.10.12.

## Generation ownership

Ordinary control owns one generation counter; Watchdog control owns independent
scheduler and work-attempt counters. Private scheduled, running and awaiting-work
states no longer repeat their active generations. Inactive control retains
allocation history. Public snapshots keep their existing shapes and values,
projecting active generations from the control counters.

Production transition inspection established that each removed active-state
generation equals its corresponding control counter: arming and dispatch advance
the counter before replacing state, retained successors keep the scheduler
counter, and running requests only arbitrate pending commands. Cancellation
retains its existing allocation and exhaustion behavior. Watchdog dispatch still
checks both increments and the successor deadline before changing either counter.

Callback acceptance, running-work authorization, provider installation and effect
confirmation retain their state, exact claim and role checks alongside the proper
counter comparison. Tokens and provider handles keep their independent generation
stamps; effect confirmation keeps its applied-generation marker. No allocation
clock, callback lifetime or failure/recovery path is merged.

Exhaustion fixtures now seed allocation history before scheduling. Ordinary
fixtures arm a real callback at `u64::MAX`; Watchdog fixtures seed far enough
below that limit for the initial arm, replacement or dispatch needed by each subject.
The old helper that changed the counter beneath an active ordinary callback is
removed. Its replacement requires inactive control. Existing fixtures preserve
duplicate-ensure, stale-delivery, atomic allocation, terminal reason, provider
cleanup, declaration lifetime and retained-successor assertions.

## Provider binding

The registry's provider installation match selects the wakeup or work slot while
validating policy, role, state and callback generation. It no longer computes
validity separately or repeats policy/role selection through
`provider_slot_mut`. That helper remains at callback consumption, where its
validation is needed.

Exact identity and claim lookup still precedes slot selection. Invalid state,
role or generation still returns `StaleCallback` with the rejected handle, and
occupied slots still return `ProviderHandleAlreadyOwned` without replacement.
The runtime remains the owner of rejected-handle cleanup outside registry borrows.
Effect confirmation and public-control retirement remain separate from Watchdog
work-message rollback. Public API, observations and recovery semantics are unchanged.

## One workspace formatting owner

`make fmt` and `fmt-check` now cover the root and `testing/` workspaces.
`testing-check` invokes the canonical formatting check before its existing nested
probe lint configurations. The commit hook and repository/CI gates already invoke
`fmt-check`, so they receive the complete scope without separate formatter recipes.

The existing hook fixture adds two minimal workspaces using the production
Makefile. It stages unformatted nested Rust, restores a formatted working copy,
and leaves unrelated root Rust dirty. The hook must reject the nested staged file
without changing either working copy or the index. Staging the formatted nested
copy must then pass while preserving the unrelated root edit. The fixture invokes
the real formatter but builds neither workspace.

## Observation contract and evidence ownership

The observability contract describes ordinary exact reconciliation as current
behavior rather than a prepared 0.9.0 change. Its Canic projection tables are
explicitly scoped to the recorded exact-0.5.0 baseline. Historical adapter and
composition evidence stays in the adoption receipts, while architecture owns
the requirements for qualifying a new combined subject. The repeated open
qualification verdict is removed. No current downstream adoption is claimed.

## Churn correctness and memory observations

The PocketIC churn subject still replaces 32,768 distant deadlines, cancels the
owned wakeup, completes 64 immediate work units and advances past the cancelled
deadlines. It retains the declaration, handle, work-count and stale-delivery
assertions, the nondecreasing page-extent check, and all reported page extents.

Positive page growth is no longer required for success: queued records can use
existing allocation capacity. The renamed subject is
`tests::provider_replacement_churn_preserves_cancellation_and_reports_memory`.
The pinned provider's cancellation limitation remains documented in `SAFETY.md`;
this change establishes neither a provider memory cap nor a new allocation result.

## Release advisory

The prose advisory no longer exempts the removed `Open release line:` status
format. Its clean fixture uses the current workspace-version projection. Target
candidate and next-action warnings, missing-file handling, and the pre-mutation
fail-open contract remain in place. No obsolete-name regression fixture is added.

## Delivery and verification scope

The generation and provider-binding simplifications make this a code-bearing patch
alongside formatting, evidence, documentation and release-tooling changes. Public API,
dependencies, Cargo versions, lockfiles and generated artifacts are unchanged.
The complete deployment gate remains required and maintainer-owned. The
generation change is private and preserves the public generation advancement
contract; no migration, compatibility alias or generated artifact is introduced.

Changed Rust is formatted. Diff whitespace, current 0.10.11 release
truth and read-only 0.10.12 changelog
and note/handoff preflight checks passed. References to the former unnamed note
and old churn subject were removed. Cargo remains at 0.10.11 and the 0.10.12
changelog section stays undated until the maintainer runs the version helper.
Tests, builds, lint gates and release execution remain maintainer-owned and were
not run.
The focused execution subjects include the existing registry provider-role and
detachment fixture, runtime binding rejection/restoration and Watchdog
dispatch-failure fixtures, `scripts/ci/test-git-hook.sh`, and the release-gate
fixtures that exercise formatting callers. They also include the renamed
PocketIC churn test,
`scripts/release/test-release-prose-warning.sh`, and the existing
`scripts/release/test-version-preparation.sh` advisory-ordering fixture. No passing
execution result or new recovery, performance or memory-bound evidence is claimed.

Generation verification also includes the ordinary control tests and registry
running-work boundary, duplicate-ensure, Watchdog paired-exhaustion, terminal
failure/lifetime, retained-successor and exact-replacement fixtures. Deployment
validation must exercise the existing ordinary suspension and Watchdog PocketIC
subjects. Static transition review and formatting are not fresh execution or
rollback evidence.
