# 0.10.13 directive failure ownership

Status: released 0.10.13.

## Canonical directive failures

Private ordinary directive resolution now returns `TimerControlFailure` directly.
The private `DirectiveError` enum, its schedule-error wrapper conversion and the
registry's `map_directive_failure` translation are removed. The schedule owner
classifies invalid callback successors, and the registry still owns terminal
state, completion accounting, declaration removal and provider effects.

Missing configured cadence still produces `DirectiveNotAllowed`; an oversized
retry delay produces `DelayOutOfRange`; and checked deadline overflow produces
`DeadlineOverflow`. These are the same classifications previously selected by
the registry mapper. Explicit scheduling requests continue to return
`ScheduleError` at their input boundary, without terminal callback accounting.
No new public error conversion or compatibility alias is added.

Arbitration still selects authoritative commands before resolving a discarded
callback proposal. Explicit invariant failure remains terminal, and resolution
failure still records an invariant completion with the reported work count and
the same cleanup/lifetime behavior. The public directive-snapshot conversion
remains an inert, independently checked projection; it is not a scheduling path.

## Verification and delivery scope

The existing schedule-resolution fixture now checks oversized retry delays and
recurrence deadline overflow alongside missing cadence and retry deadline
overflow. Existing ordinary completion, exact-reconciliation, cancellation,
unregistration and lifetime fixtures remain the focused registry subjects.
The snapshot projection's oversized-delay negative test is retained.

Changed Rust is formatted. Diff whitespace and read-only changelog and
release-note/handoff checks passed. Tests, builds, lint gates and deployment
validation remain maintainer-owned and were not run. No fresh recovery or
performance evidence is claimed.

This is a private simplification suitable for a patch. Public API and snapshot
shapes are unchanged, so a 0.11.0 hard cut is not needed for this change. Cargo
remains at 0.10.12; both lockfiles, dependency versions and Git release state are
unchanged. The 0.10.13 changelog section stays undated until the maintainer runs
the version helper. Downstream work remains deferred.
