# 0.10.23 reconciliation validation and scheduler failure ownership

Status: released 0.10.23.

## One reconciliation validation owner

`TimerRegistry::reconcile_ordinary` directly validates its exact claim and ordinary
policy before deciding between cancellation and schedule resolution. The
single-caller `validate_ordinary_claim` helper is deleted. Its validation order and
typed errors are preserved; request execution retains its own policy and control
checks. Public API, snapshots, provider binding and lifetime behavior are unchanged.

The existing `watchdog_terminal_cancellation_makes_queued_callbacks_stale` fixture
now checks ordinary reconciliation against an armed Watchdog declaration with
inactivity, a valid absolute deadline and an oversized relative delay. Every
request must return `PolicyMismatch` with an unchanged complete inventory. The
oversized delay distinguishes policy validation from schedule parsing. Its
existing dispatch, cancellation, stale-delivery and accounting assertions remain.

## One Watchdog scheduler failure path

`TimerRegistry::begin_watchdog_scheduler` checks paired generations and the cadence
successor deadline before committing either allocation counter or the dispatched
state. Both errors now use one terminal finalization branch, deleting repeated
work-cleanup effect construction and transient-lifetime finalization.

Generation validation still precedes deadline validation, so simultaneous
exhaustion and deadline overflow reports `GenerationExhausted`. Accepted scheduler
and unacknowledged-attempt accounting still precede these checks. Failure stops
control with the same reason, clears queued work and removes only transient
declarations. Successful dispatch retains its token, deadline and ordering behavior.

`watchdog_checked_generation_exhaustion_is_terminal_and_atomic` retains its initial
scheduler-allocation case and now runs attempt exhaustion both at ordinary time
and at `u64::MAX`, where cadence addition would also overflow. Both cases require
the generation failure, work-cleanup effect, inactive terminal state and unchanged
allocation counters. The separate deadline-overflow fixture still covers that
error when generation allocation is available. Watchdog terminal-lifetime and
native queued-work cleanup fixtures remain focused verification subjects.

## Verification and delivery scope

This private, behavior-preserving simplification fits the 0.10 patch line. Existing
ordinary reconciliation and pending-command fixtures remain verification subjects
alongside the extended negative fixture. Watchdog scheduler exhaustion, deadline
overflow, terminal-lifetime and queued-work cleanup subjects cover scheduler
finalization. No new test harness or fixture is added.

Changed Rust is formatted. Diff whitespace, staged-changelog validation,
release-note preflight and current release-truth checks passed. Tests, builds,
lint gates and deployment validation remain maintainer-owned and were not run.
No new recovery, performance or provider-heap guarantee is claimed.

Repository metadata already records 0.10.22 as released, so this follow-up is
prepared under the next undated patch heading. The maintainer's existing changelog
edit is preserved. Cargo versions and both lockfiles remain unchanged; all Git
staging and release execution remain maintainer-owned. Downstream work stays deferred.
