# 0.7.0 immediate Watchdog continuation

Status: released 0.7.0.

## Scope

- Add `WatchdogDecision::ContinueImmediately` so a normally completed callback
  that made progress can move its exact pre-armed cadence successor to deadline
  now. Execution remains a later replicated scheduler message and never becomes
  synchronous recursion.
- Add `WatchdogRegistration::ensure_scheduled_immediately()` and
  `WatchdogContext::ensure_scheduled_immediately()` for immediate demand outside
  and inside the exact running work attempt.
- Add `WatchdogReconcileState::ScheduledImmediately` so lifecycle
  reconstruction can arm the first actionable Watchdog wake-up immediately.
- Keep `WatchdogDecision::Continue` cadence-based and `WatchdogDecision::Stop`
  terminal. No retry policy, persisted state, snapshot field, ordinary timer,
  second Watchdog, or alternate provider path is added.

## Compatibility and hard-cut boundary

`reconcile_watchdog` now accepts the policy-specific
`WatchdogReconcileState::{Inactive, Scheduled, ScheduledImmediately}` instead
of `TimerReconcileState`. This public pre-1.0 hard cut has no compatibility
alias, deprecated forwarder, feature-gated legacy path, or dual reconciler.
Consumers must update at the `0.7.0` minor boundary.

The declaration, claim, generation, callback, pending-command, and private
provider-handle flow remains the sole scheduling authority. Registry capacity,
the at-most-two Watchdog handle bound, closed runtime states, callback roles,
snapshot shape, and persisted-state count are unchanged.

## Scheduling and arbitration

- An inactive immediate request arms one zero-delay scheduler wake-up. A later
  cadence deadline is replaced; equivalent, earlier, repeated, dispatched, and
  running requests coalesce without another authoritative wake-up.
- Every accepted scheduler message still commits a cadence safety successor
  before it queues work. A trap or instruction exhaustion before work returns
  therefore leaves that successor available.
- Normal immediate completion rotates and replaces that exact successor at
  deadline now. Replacement or confirmation failure traps, allowing replicated
  message rollback to recover the previously committed cadence successor.
- Invariant failure, stop, cancellation, and unregistration override callback
  continuation. Unregistration is sticky; later cancellation wins; a later
  explicit ensure may re-enable pending cancellation as before; and cadence
  ensure cannot downgrade pending immediate demand.
- Stale scheduler and work tokens remain inert through existing claim,
  generation, and attempt checks.

Immediate authority is visible through existing observation fields:
`next_deadline_ns`, continuation scheduling mode, zero requested/armed delay,
and the established request, arm, and coalescing counters. Callback decisions
continue not to count as explicit scheduling requests.

## Validation and evidence

- All 94 native tests pass, including focused initial, replacement,
  coalescing, overdue-cadence snapshot, running-work arbitration,
  cancellation, unregistration, provider-fault, and stale-token cases.
- The pinned PocketIC 15 matrix passes all eight Watchdog subjects, including
  zero-delay initial scheduling and immediate successful continuation without
  cadence-time advancement, plus existing trap and actual
  40-billion-instruction exhaustion recovery.
- Formatting, warning-denied Clippy and rustdoc, Wasm compilation, offline
  packaging, provider-boundary checks, Rust 1.88 workspace checks, and every
  supported nested-probe lint configuration pass.
- In one same-callback PocketIC observation, immediate replacement reports a
  27,811-instruction work interval versus 19,451 for cadence retention, with
  scheduler/work cycle deltas of 30,742,889 and 30,732,414. These are accepted
  runtime intervals and pair-level cycle deltas, not full-message totals.
- The optimized Watchdog cohort is 262,791 bytes versus 261,914 bytes for
  after-completion: +877 bytes (0.335%).
