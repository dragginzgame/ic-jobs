# 0.10.17 lazy runtime initialization

Status: released 0.10.17.

## One initialization decision

`initialize_runtime` uses the existing optional runtime slot's
`get_or_insert_with` operation to create the registry only when absent. The
initializer reads canister version and time and constructs the initial epoch.
Repeated calls return the epoch held by that same registry without re-reading
the system facts and constructing a discarded candidate epoch.

The fallible mutable borrow remains before slot access. A conflicting borrow
returns `TimerError::RuntimeBusy`; first initialization creates one empty
registry, and subsequent calls preserve its state and original epoch. System
fact reads are synchronous and do not invoke consumer work or provider timer
operations. The slot remains the sole registry owner, with no new flag, cache,
initialization state or compatibility path.

Public signatures, epoch values, lifecycle ownership, scheduling, provider
effects and observations are unchanged. This private simplification fits the
0.10 patch line. No performance or instruction savings were measured.

## Verification and delivery scope

The existing `runtime::tests::initialization_is_required_and_idempotent` fixture
retains pre-initialization rejection, repeated initialization after advancing
time, exact first-epoch values and empty inventory assertions. It now also
checks `RuntimeBusy` while a runtime borrow is held, then verifies that the
original inventory epoch remains available after releasing the borrow. No
test-only system-read counter or implementation-mirroring fixture is added.

Tests, builds, lint gates and deployment validation remain maintainer-owned and
were not run. The fixture requires maintainer execution; no new recovery or
PocketIC result is claimed.
Changed Rust was formatted; diff whitespace and read-only changelog and
release-truth checks passed.

Release-impact inspection retained the existing conservative source-based
classification. A read-only `cargo package --list` confirmed that dedicated
native test modules are shipped in the crate archive. Test-only edits there
change published source even when runtime behavior is unchanged; changes
outside that archive's source/manifests remain separately classified. No
classifier exemption or reduced validation gate was added.

Cargo remains at 0.10.16, both lockfiles and dependencies are unchanged, and the
0.10.17 changelog heading is undated. Version mutation, staging and all Git and
release execution remain maintainer-owned. Downstream work remains deferred.
