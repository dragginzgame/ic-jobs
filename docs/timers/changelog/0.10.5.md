# 0.10.5 state and request ownership

Status: released 0.10.5.

## One inactive state and reason

Private Watchdog control previously stored its state and inactive reason in
separate fields. The reason was only observed while inactive, but active states
still carried that metadata and each terminal transition assigned both fields.

`WatchdogState::Inactive` now contains the reason. The independent field and its
paired writes are deleted. Fresh declarations construct `NeverScheduled`;
checked termination and provider failure construct `ControlFailure`; successful
cancellation constructs `Cancelled`; work completion selects `InvariantFailure`,
`Cancelled` or `Stopped` before constructing the inactive state. Every inactive
construction must supply its reason, and snapshot projection reads it directly.

Inactive cancellation remains a no-op that preserves the existing reason.
Invariant failure still takes precedence over pending cancellation. Paired
generation allocation, counters, pending-command cleanup, declaration lifetimes,
provider effects and their ordering are unchanged. Ordinary control and its
registry-owned inactive metadata remain separate from this Watchdog cleanup.

This is a private, volatile representation change with no public API or snapshot
change, storage transition or compatibility path. It fits a patch release.

## One cancellation removal decision

Cancellation already decides removal from the resulting policy state and
declaration lifetime. Its ordinary failure branch finalizes transient cleanup
before returning; its Watchdog branch handles both successful cancellation and
checked failures, which terminate control as inactive. The trailing call to
failure cleanup therefore repeated a removal decision that was already complete.

The shared cancellation exit now applies its policy decision through
`remove_after` once. Running work still retains its declaration and queues the
pending command. Inactive and cancelled transients are removed; retained
declarations stay inspectable. Ordinary early failure handling, error reasons,
generation allocation, counters and callback cleanup effects are unchanged.
Other operations retain failure cleanup where they still need it.

## One ordinary request-observation path

Recurring ordinary ensure previously updated request counters, coalesced counters
and requested delay itself when already scheduled, bypassing the shared ordinary
request handler. That duplicated observation updates and a no-op exit.

It now submits the existing scheduled deadline to `request_ordinary`, where
ordinary control retains the equal deadline and the canonical request handler
records coalescing. Inactive and running declarations still calculate a checked
cadence deadline before that call. This preserves the special case that an
already scheduled declaration succeeds even when a hypothetical new deadline
would overflow, or its generation allocator is exhausted. It retains exact
scheduled deadlines and their observed mode rather than advancing them to the
current cadence. Running-work arbitration and validation ordering are unchanged.

## Callback lookup owns claim selection only

Private callback lookup no longer accepts a redundant expected-role argument.
Installation and arm confirmation passed the token's own role; dispatch
confirmation had already checked its scheduler role through effect-shape
validation. The helper selects identity and exact claim. Provider installation
and effect confirmation retain their existing policy, role, generation and state
checks; slot validation and dispatch work-token validation remain unchanged.
No role-validation boundary is removed.

## Focused verification

The existing Watchdog generation-exhaustion and deadline-overflow fixtures now
assert the public inactive state and exact failure reason instead of the old
private unit variant. Their generation atomicity and pending cleanup assertions
remain. Maintained fresh-declaration, terminal-lifetime, result-matrix, nested
cancellation and provider-failure fixtures cover the other affected paths.
The existing Watchdog terminal-failure/lifetime matrix now includes cancellation
of scheduled and dispatched work with exhausted scheduler or attempt generation,
respectively. It checks retained failure state, transient removal and fresh claim
identity, wakeup-only versus wakeup-and-work cleanup, and no successful cancellation
count. The ordinary matrix already covers cancellation exhaustion for both policies
and lifetimes; runtime fixtures retain actual handle cleanup and cancellation
during running work.
The existing recurring duplicate-ensure fixture now covers both cadence and
explicit exact schedules, an exhausted generation allocator and a timestamp
whose hypothetical cadence successor overflows. It checks unchanged state,
mode and armed delay, cadence request observations, one coalesced request and
acceptance of the original callback token. Existing provider-role and malformed
dispatch confirmation fixtures protect the callback lookup callers.
Tests, builds, lint gates and deployment validation remain maintainer-owned;
none were executed during preparation. No new runtime, recovery or performance
result is claimed. Downstream work remains deferred.

Changed Rust is formatted. Diff whitespace, current release-truth and read-only
0.10.4-to-0.10.5 note/handoff checks passed. The public crate facade, Cargo
manifests, both lockfiles and Git index are unchanged. No version bump or Git
release operation was run during preparation.
