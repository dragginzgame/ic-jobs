# 0.10.19 registry command and effect ownership

Status: released 0.10.19.

## One pending-command decision

`select_pending_ordinary` matches the current command and incoming request
together. Sticky unregistration has one branch rather than an early return
followed by an unreachable duplicate. Exact reconciliation still supersedes
other pending commands. Ensure requests still select the earliest demand,
retain the existing schedule at equal deadlines, and convert a retained exact
request into ordinary scheduling demand.

Cancellation, completion arbitration, input validation, policy checks, callback
authorization and lifetime removal keep their existing owners. The ordinary and
Watchdog selectors remain separate because their command contracts differ.
There is no public API or snapshot change and no compatibility path.

## Transition capability and cleanup construction

Ordinary completion and Watchdog scheduler dispatch use the existing `token_for`
constructor with the accepted callback's claim. They no longer assemble identity
and registration generation independently from the token and registry entry.
Ordinary completion already verifies exact running-work ownership, and Watchdog
scheduler dispatch already verifies the claim, role, state and generation before
building successors. Those checks establish that the token's claim matches the
entry. Newly allocated callback generations and policy-specific roles remain
explicit at each call site; queued tokens still own independent identities.

`clear_callbacks`, a forwarding wrapper around `RegistryEffect::ClearCallbacks`,
is removed. Unconditional cleanup effects are constructed directly. Watchdog
cancellation selects its cleanup effect once from the pre-cancellation state and
uses it for either successful cancellation or generation exhaustion. It still
clears only wakeups while scheduled, clears wakeup and work while dispatched,
and defers cancellation while work is running. Failure and success keep their
different terminal reasons and accounting.

Watchdog scheduler arming uses the existing conditional wakeup cleanup helper
when generation allocation fails. Initial arming still emits no cleanup;
replacement still clears the owned wakeup. Scheduler dispatch failures still
clear work, while completion stop still clears the committed successor. No
provider ordering, handle ownership, confirmation or rollback rule is merged.
These changes delete a forwarding function and repeated construction decisions;
no allocation, instruction or performance savings were measured.

## Verification and delivery scope

Existing ordinary fixtures are extended to check sticky unregistration after
later ensure, reconciliation and cancellation requests, and to check scheduling
mode and relative-delay observations when competing deadlines are equal.
Assertions exercise registry operations and snapshots rather than private
selector structure. These are native transition subjects; they do not establish
IC rollback or provider delivery behavior.

Tests, builds, lint gates and deployment validation remain maintainer-owned and
were not run. Focused subjects are
`explicit_unregistration_consumes_scheduled_and_running_claims`,
`once_coalesces_and_rotates_generations_while_nested_schedule_wins` and
`relative_exact_reconciliation_preserves_request_observations_after_suspension`.
The existing ordinary request-order and directive/failure fixtures also remain
relevant to preserved behavior.
Existing running-work authorization, provider-role/detachment, dispatch
confirmation, Watchdog cancellation and terminal-failure/lifetime fixtures
cover the additional construction changes. Their assertions are retained;
the cleanup-effect expectation now constructs the enum directly. No source-text
or private-constructor enforcement test is added.
Maintainer Clippy feedback reported the Watchdog precedence fixture at 101 lines
against the 100-line limit after the direct cleanup-effect assertion. Its later
reconciliation setup is shared across the cancellation and unregistration
cases. All nine scenarios, command ordering and assertions are preserved,
without adding a lint exception. Clippy has not been rerun by the contributor.
Changed Rust was formatted. Diff whitespace, staged-changelog validation,
release-note preflight and current release-truth checks passed.

This private behavior-preserving cleanup fits 0.10.19. Cargo versions, both
lockfiles, dependencies and generated artifacts are unchanged. The changelog
heading remains undated; version mutation and all Git/release execution remain
maintainer-owned. Downstream work remains deferred.
