# 0.8.1 Rust 1.99 and CI maintenance

Status: released 0.8.1.

## Changes

- Update the development pin and hosted CI to Rust 1.99.0 while retaining
  Rust 1.88.0 as the minimum supported Rust version.
- Lint every supported nested probe configuration with warnings denied on
  both toolchains in hosted pull-request and main checks.
- Use equality assertions for empty native inventory collections so failures
  report unexpected contents, and collapse the runtime probe's unregister
  check into an equivalent let-chain. Both changes satisfy Rust 1.99 Clippy.
- Align current documentation with the 0.8.0 API, exact dependency example,
  current toolchain and nine maintained PocketIC Watchdog subjects. Clarify
  release state, historical downstream evidence and observation semantics.
- Address Toko Miner IC-TIMERS-001 with dated registry-publication evidence and
  the scoped Canic 0.110.33/IcyDB 0.261.0 composition receipt. The old lifecycle
  blocker is resolved for that subject; current deployment and cost comparisons
  remain unverified. See the [downstream record](../adoption/toko-miner.md).
- Address IC-TIMERS-002 by removing the obsolete
  `begin_watchdog_scheduler` line-count suppression and replacing the nine
  active Clippy suppressions with expectations carrying explicit reasons.
  Atomic transitions and the coherent lifecycle fixture remain intact.

There is no runtime behavior, public API or dependency change. The release set
the workspace package version to 0.8.1, the changelog is dated 2026-10-02, and the local
`v0.8.1` tag points to the release commit. Read-only inspection on 2026-10-03
corroborates publication: the cached registry package's VCS metadata identifies
`c27f54ae64d1c667e9563925a9d7e4791d9359e3`, and Toko Miner's registry
lockfile selects one timer 0.8.1. See the [dated adoption record](../adoption/toko-miner.md).

  warning-denied Clippy/rustdoc, Wasm checking and offline package verification.
- `make msrv`, the changed inventory test on Rust 1.88.0,
  `make testing-check` and `make testing-check MSRV=1.99.0` pass.
- The runtime probe passes Wasm checking on Rust 1.99.0, and hosted workflow
  syntax passes `actionlint`.
- After the feedback fixes, `make ci`, `make msrv` and every nested-probe
  lint configuration pass again. Strict production Wasm Clippy passes on
  both Rust 1.99.0 and Rust 1.88.0 without unfulfilled lint expectations.
  Local documentation link targets and the pinned downstream receipt hash
  also pass verification.

The maintenance validation recorded above did not rerun PocketIC recovery or
policy-cohort suites and is not a receipt for the complete release gate. Future
version bumps must run the complete gate through the release helper.

## Remaining advisory feedback

IC-TIMERS-003 remains advisory: supplemental root all-target Clippy on Rust
1.88 reports lifecycle-test cognitive complexity of 44/25. The required root
MSRV gate compiles all targets; strict root Clippy uses the development
toolchain. This patch addresses IC-TIMERS-001/002 without changing that gate
or adding a complexity suppression. The ordered lifecycle fixture retains
its reconstruction and commit-guard assertions.

Disposition on 2026-10-03: retain the coherent fixture and the current gate
scope. Its ordered assertions exercise reconstruction and commit-guard demand
against the same evolving runtime; splitting those phases would obscure that
contract without addressing a runtime defect. Do not add a blanket suppression,
raise the MSRV or introduce a new mandatory gate for this supplemental diagnostic.
The old diagnostic was not rerun during the feedback review.
