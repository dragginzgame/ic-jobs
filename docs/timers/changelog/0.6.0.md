# 0.6.0 atomic inventory epoch

Status: released 0.6.0.

## Scope

- Add `TimerInventorySnapshot { epoch, timers }` as the single complete
  inventory observation.
- Expose the initialized runtime epoch even when the bounded registry is empty.
- Return timers in the registry's existing deterministic identity order.
- Keep `timer_snapshot()` for focused lookup by known identity.
- Hard-cut the superseded bare-vector `timer_snapshots()` function without an
  alias, deprecated forwarder, compatibility feature, or alternate registry.
- Clarify that instruction values measure the accepted `ic-timers` execution
  interval, not application code alone. Memory reads bracket that interval;
  provider entry/exit and the summary write remain outside its instruction
  delta.
- Clarify that a terminal `RemoveWhenStopped` callback can remove its
  declaration before the final measurement is retained because no timer
  remains to observe it.

## Migration

Replace:

```rust,ignore
let timers = timer_snapshots()?;
```

with:

```rust,ignore
let inventory = timer_inventory()?;
let epoch = inventory.epoch();
let timers = inventory.timers();
```

Use `inventory.into_timers()` when the adapter needs to consume the ordered
vector. An empty `timers()` slice is a valid initialized inventory and still
has a meaningful epoch.

## Downstream boundary

Canic and IcyDB independently resolve exact `ic-timers` 0.5.0. Canic exports
schema-3 timer, instruction, and memory observations without a second
scheduler; its exact-0.3.8/schema-2 subject remains historical.

The 0.6 adapter update does not itself prove combined composition. One final
Wasm must still demonstrate one resolved registry, both owners in one
inventory, synchronous lifecycle reconstruction, IcyDB Watchdog recovery, and
continued Canic timer progress. That evidence is blocked on Canic's
lifecycle-composition seam rather than an `ic-timers` scheduler change.
