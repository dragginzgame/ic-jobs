# 0.10.4 ordinary completion and failure ownership

Status: released 0.10.4.

## One completion authorization boundary

The canonical registry rejects ordinary completion unless the token owns the
exact identity, claim, ordinary work role and running generation. The only
production call into private ordinary control occurs after that validation,
in the same provider-call-free transition. Directive resolution and successor
selection neither suspend nor invoke consumer code or change the running state.

Private `complete_running` therefore applies an already-authorized successor
decision without receiving and checking the callback generation again. The old
`complete` operation, redundant stale check and impossible stale-result branch
are removed. No public validation boundary or stale-token rejection is removed.
The obsolete control-local stale-generation fixture is deleted; the maintained
registry rejection matrix exercises that invariant at the live entry point.

## Canonical checked failures

Ordinary schedule, cancellation and authorized completion now return the existing
`TimerControlFailure` value directly. The private `TimerControlError` enum and
`map_control_failure` conversion are deleted. The registry's inconsistent-schedule
guard reports `DirectiveNotAllowed` directly, preserving its existing classification
instead of manufacturing a stale-completion error for a scheduling operation.

Generation allocation remains checked before state mutation. Rejected allocation
preserves the prior state until registry terminal cleanup; stopping an exhausted
running generation still allocates nothing. Retained/transient lifetimes, typed
public errors, observations, arbitration, provider cleanup and rollback rules
retain their existing behavior. Public API and snapshot shape are unchanged;
this private simplification fits a patch release and retains no compatibility path.
