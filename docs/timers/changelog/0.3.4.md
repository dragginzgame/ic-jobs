# 0.3.4 adoption-gate hardening

Status: released 0.3.4.

## CI portability

- Runner-executed release-wiring and provider-boundary checks use portable
  `grep` primitives rather than assuming `rg` is installed.
- Release-truth checks verify that Cargo, the dated changelog, current status,
  and version-specific note agree after a bump.

## Reconciliation contract

- `reconcile_once`, `reconcile_after_completion`, and `reconcile_watchdog`
  always install retained lifecycle declarations and no longer accept a
  `DeclarationLifetime` argument.
- Transient `RemoveWhenStopped` callbacks remain explicit direct registrations.
  This prevents a reconciliation slot from retaining a capability after its
  canonical declaration has intentionally removed itself.

## Provider-failure evidence

- Focused native tests cover initial and replacement `Once` binding failures,
  `AfterCompletion`, a watchdog successor installed before its work binding
  fails, effect-confirmation failure, and `RemoveWhenStopped` cleanup.
- Every case proves provider handles are cleared and canonical state is either
  retained as `ProviderBindingFailed` or removed according to its declared
  lifetime.

## Validation

- Normal CI passes with 70 native tests, warning-denied Clippy, rustdoc, Wasm
  compilation, offline packaging, and the portable release/provider checks.
- Rust 1.88 workspace checking and every supported nested-probe Clippy feature
  configuration pass.
- PocketIC was not rerun for this candidate because the scheduler/work protocol
  and provider binding implementation are unchanged; the maintainer-owned
  release bump retains the complete PocketIC release gate.
