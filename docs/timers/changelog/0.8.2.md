# 0.8.2 runtime and validation hardening

Status: released 0.8.2.

## Changes

- Stop `repository-check` immediately when impact classification or any check
  fails. `release-impact` also propagates classification failures.
- Run `bash -n` separately for the hook and every CI, development and release
  script, so errors in later files fail the syntax gate.
- Check complete public export statements for provider/platform names,
  including qualified paths, grouped imports, multiline statements, local
  import aliases and public type aliases. Platform items have crate visibility,
  backed by compiler rejection fixtures. One explained Clippy expectation keeps
  that deliberate restriction despite the module already being private.
- Resolve both workspace dependency graphs for post-bump locked metadata
  checks, rejecting stale path-package versions. Reject failed Git diff and
  untracked-file enumeration inside the impact classifier.
- Remove `RemoveWhenStopped` declarations on checked terminal control failures.
  One control-operation path detaches provider handles before mutation, so
  terminal entry removal cannot discard an armed wake-up or queued work.
  Watchdog scheduler dispatch also detaches its remaining handles before a
  terminal transition. Retained declarations stay inactive and observable.
- Reuse the Watchdog scheduler-arm implementation for successful work's exact
  successor replacement; remove duplicated reconciliation detachment code.
- Exercise successful validation and negative fixtures for classification,
  each repository check, each shell-script directory, private module ownership,
  a second direct provider path and public platform exports. Run these fixtures
  through the existing `release-check` gate.
- Refresh the handoff and 0.8.1 note to reflect the completed version bump and
  local release tag, without asserting registry publication.
- Prepare version bumps from the current worktree without a preparatory
  commit or test run. Keep the complete gate in user-operated `release-*`
  targets. `AGENTS.md` reserves tests, commits, tags, pushes and publication
  for the user. Update the isolated workspace fixture to check that preparation
  updates both lockfiles without running deployment validation, committing,
  tagging or changing unrelated work.

The transient failure cleanup corrects terminal cleanup for the existing
`RemoveWhenStopped` lifetime contract; this is crate-impacting work. No public
item, signature, snapshot shape or dependency changes. The backwards-compatible
fix uses the 0.8.2 patch release. The workspace version and both lockfiles are
updated; commits, tags, pushes and publication remain user-owned.

## Validation — 2026-10-03

The complete release gate passed before the final separation of version
preparation from deployment testing. Those final workflow edits and their
updated regression fixtures have not been rerun, at the maintainer's request.

- `make ci` passes, including 108 native tests, warning-denied Clippy/rustdoc,
  Wasm checking, package verification and all release-helper regression tests.
- `make msrv`, every nested probe lint configuration on Rust 1.88.0 and 1.99.0,
  and strict production Wasm Clippy on both toolchains pass.
- Both root and testing lockfiles pass dependency-resolving offline locked
  metadata checks. Negative fixtures reject each stale lockfile without
  mutation, both internal Git failure paths, direct/aliased platform exports,
  and unrestricted platform items. Compiler fixtures independently reject
  indirect re-exports and public type aliases.
- `make pocketic-watchdog pocketic-cohorts` passes all nine maintained Watchdog
  subjects and all four policy cohorts using audited PocketIC 15.0.0 and SHA-256
  `29472ea4433b30a280676c4e22e369d79d5ba6ee1b4d48bab32ebe7d0ad2b4bb`.
- ShellCheck passes for every changed/new check script; `git diff --check`
  passes.

Boundary generation/timestamp failure cleanup is backed by native evidence,
including retained/transient lifetime matrices and actual queued-work cleanup,
not a new PocketIC recovery subject. Cohort measurements report accepted
execution intervals; no performance improvement is claimed. Registry capacity,
the at-most-two Watchdog handle bound and the two-message protocol remain intact.
