# 0.9.2 implementation and evidence-tooling simplification

Status: released 0.9.2.

The sections below retain the implementation and preparation record. The
Delivery section records the released subject and supersedes their pending
validation statements for the maintained hosted gates.

## Implementation

Ordinary deadline requests select the existing `WakeupArm` value directly instead
of passing through an optional replacement flag. Completion checks the requested
successor once and allocates its generation only when a successor is present.
Checked allocation still precedes state mutation. An exhausted running generation
can stop without allocating another generation, while attempts to rearm it fail
without changing running state. The existing exhaustion test covers both cases.

Instruction summaries use sample count to distinguish empty observations from
recorded measurements, as memory-page summaries already do. The private latest
and maximum slots no longer carry separate optional states. Public getter types
and observations remain unchanged: an empty summary returns `None`, the first
zero measurement returns `Some(0)`, and latest/maximum continue updating after
sample count or total saturates. A focused fixture covers those boundaries.
Derived Debug output reflects the new private field representation; no persisted
or wire format is changed. No layout, binary-size or performance savings are
claimed.

Callback binding classifies finalized registry control failures separately from
unexpected errors. Every unexpected error follows the existing callback-role
recovery rule without listing all `TimerError` variants again. Watchdog work
traps so IC rollback preserves its committed successor; ordinary work and
scheduler failures keep their fail-closed provider cleanup. Existing provider
binding, restoration and rollback fixtures remain.

Ordinary failed completion now has one owner for stopping control, clearing the
pending command, projecting Stop and recording the completion. Consumer invariant
failure still returns a normal transition with an invariant inactive reason;
checked control failure still returns its typed terminal error and records an
invariant completion with the original work count. Both paths already validate
the exact running token before finalization, and a rejected checked successor
leaves that running state unchanged. The repeated generation check in the old
helpers is removed. Existing tests cover illegal recurrence, explicit invariant
failure, deadline overflow, generation exhaustion and retained/transient lifetime.
The retained-completion fixture now checks both paths' public outcome, work count,
failure time, Stop observation and completion/cancellation counters.
The ordinary lifetime matrix also covers successor-generation exhaustion during
completion for both ordinary policies and both declaration lifetimes.
The maintainer's lint run rejected its `subject != "initial"` branch under
Clippy's `if_not_else` rule. The fixture now handles the initial case first with
`subject == "initial"`; scheduling and completion setup remain in the other
branch. No lint suppression or coverage change is added. A rerun is pending.
The reported optional-failure match in `stop_ordinary_completion` now uses
`Option::map_or_else`: absence preserves the consumer invariant completion and
normal transition; presence retains the typed terminal control failure and
original work count. Stop bookkeeping is unchanged. Clippy was not rerun.

## Registry ownership

Each entry now stores one policy-specific payload containing its matching
control, callback and cadence. An ordinary payload without cadence is Once;
one with cadence is AfterCompletion. Watchdog owns its synchronous callback,
cadence and Watchdog control together. Public policy observations are derived
from the payload; the independent stored policy and callback enum are removed.
Scheduling mode remains separate because it records the effective scheduling
request, not just declaration policy.

Registration constructs the typed payload directly. Ordinary and Watchdog
transitions select their matching control and cadence in one pattern instead of
checking agreement between independent variants. Callback lookup still validates
the exact running token and rejects a wrong policy through the existing ownership
error mapping. There is no callback-absent production or test entry, so the private
missing-callback error is removed. Pure registry fixtures use inert typed callbacks
that fail if accidentally invoked; their transitions use the production entry
constructors. Existing exhaustion fixtures target the new payload.
The maintainer's subsequent Clippy report identified `Entry::new` as const-capable;
it is now `const fn`, using the existing const policy projection and observation
initializer. Runtime construction behavior is unchanged; the lint rerun is pending.

The public API, snapshot model, pending-command ordering, callback invocation
outside registry borrows, provider handles and scheduler/work recovery boundary
are preserved. No wire discriminator or persisted format changes. Existing native
and PocketIC behavior evidence must be rerun by the maintainer; no new result is
claimed for this refactor.

## Release version ownership

`workspace-version.sh` owns reading and mutation of the literal canonical version
in `[workspace.package]`. Version display, bumping, staging, release truth,
committing and tag checking use it. It rejects missing or duplicated tables or
fields, invalid versions and an unexpected previous version before writing.
The writer changes only the selected value; dependency tables may precede it.
Release staging exits before Git changes if version selection fails. Both full
locked metadata checks now also require one resolved timer package at the
workspace version, rather than accepting internally coherent locks for another
package version. No parser dependency is added; the metadata check uses Perl's
standard JSON decoder.

Existing preparation fixtures cover a preceding dependency version, ambiguous
or malformed workspace metadata, rejected writes, staging failure, rollback and
unchanged dependency values. Commit and tag fixtures also place a dependency
version first. The lockfile fixture covers coherent resolution at a version
different from workspace truth. These fixtures are prepared, not executed.

## Evidence tooling

PocketIC cache and download validation use one verifier, which hashes a candidate
before executing its version command and requires both checks to succeed. Invalid
explicit overrides are rejected without modification. Automatic provisioning
still verifies a temporary download before replacing the cache and removes
temporary artifacts on failure. Rejection diagnostics reuse the failed
verification's observations rather than hashing or executing the candidate again.
The independent exact version/hash/URL guard remains; no audited pin or release
gate is weakened. Fixtures cover wrong versions, a failing version command even
with matching output, preserved cache contents and rejected-download cleanup.

The release-gate fixture now invokes the actual Make `pocketic-check` recipe with
a recording checker, replacing exact Makefile source-line assertions. It verifies
the default cache path and automatic-install flag, environment and command-line
overrides, an explicitly selected default path and an empty override. Selection
depends on whether the binary variable was supplied, not whether its value equals
the default. No binary is downloaded by this fixture; the separate binary verifier
fixture retains hash-before-execution and cache-preservation checks.

Delivery guidance assigns lockfile staging to the user consistently. The 0.5
callback-authority record marks its original Watchdog reconciliation restriction
as superseded by the 0.8 deadline contract. Current architecture documentation
describes the single entry payload and release version owner.

## GitHub feedback

The 2026-10-03 GitHub review found one open issue in this repository:
[issue #8](https://github.com/dragginzgame/ic-timers/issues/8), the supplemental
Rust 1.88 lifecycle-test complexity advisory transferred from IC-TIMERS-003.
The issue had no comments and reports no runtime or maintained-gate failure.

Its cleanup separates the five independent readiness/result cases into one
table-driven mapping test. The lifecycle fixture retains its original ordered
reconstruction, retry, stop, commit-guard rearm, terminal failure, recovery,
scheduler/work-gap cancellation and declaration-conflict observations against
the same runtime. Four measurement sample assertions share one three-round
expectation with role-specific diagnostics. The callback reads readiness once
and uses its completed work count to update pages, removing the separate match
with empty arms.

The final cleanup gives the repeated complete-round driver one test helper that
advances time and asserts scheduler then work delivery. The three initial work
rounds call it; phases observing or cancelling the scheduler/work gap retain
their separate message calls. A second helper owns the completed instruction
and memory sample assertions, using the same stopped snapshot as before.
Progress and live-handle counts are asserted together at each completed round.
The lifecycle driver retains every phase in order while the independent mapping
and measurement checks have their own scope. No generic test framework or
additional production layer is introduced.

The ordered lifecycle sequence is kept because each phase depends on the exact
retained claim and earlier runtime state; resetting or splitting those phases
would weaken that continuity evidence. The existing local `too_many_lines`
expectation remains justified by that sequence. No cognitive-complexity
suppression, MSRV increase or new mandatory gate is introduced. The current
root MSRV gate compiles all targets and development-toolchain Clippy remains
strict; nested-probe MSRV lint retains its separate required scope.

These are test-only changes, not a runtime fix or a new downstream qualification.
Formatting and diff whitespace were checked. Unit execution and supplemental
Rust 1.88 lint validation remain user-owned and were not run. No reduced lint
score is claimed. The released disposition of issue #8 is recorded below.
