# 0.9.0 ordinary arbitration and audit follow-up

Status: released 0.9.0.

## Hard cut

Ordinary completion now applies a winning exact reconciliation before resolving
the callback scheduling proposal. An overridden retry duration, recurrence
deadline, or Once recurrence proposal cannot stop an accepted exact successor.
Explicit consumer invariant failure still stops; unregistration remains sticky;
cancellation remains terminal unless superseded by a later valid request.
Without an exact reconciliation, callback policy and checked arithmetic still
fail closed. Earliest-demand ensure arbitration is unchanged.

`TimerSnapshot::latest_directive()` now exposes the effective exact `ScheduleAt`
directive when reconciliation wins, including a relative request resolved once
at request time. The selected request still supplies scheduling mode and relative
delay observations. No compatibility switch, alias or alternate arbitration path
is retained. This public semantic change requires the next minor line, 0.9.0.
At preparation on 2026-10-03, Cargo and both lockfiles selected the released
0.8.4. The automated contributor did not bump them.

## Other audit findings

- The native executor polls suspended futures only after their waker signals
  readiness. Live handle counts exclude started futures. Native coverage includes
  outside cancellation, exact reconciliation, ensure, unregister, context expiry,
  unrelated Watchdog progress and completion-time recurrence after suspension.
  The suspension helper explicitly expects Clippy's `future_not_send` lint:
  its shared `Rc` state models the same single-threaded callbacks as the runtime.
  This corrects the maintainer-reported lint failure without changing execution.
- A probe repeatedly awaits self-call gate replies while queries,
  unrelated Watchdog work and ingress control requests proceed. Once and
  AfterCompletion exercise cancellation/removal, unregister and exact scheduling;
  AfterCompletion also records its actual completion-time recurrence.
  Each closed-gate reply leads to another actual outgoing call; opening the gate
  lets the next reply resume work in its originating CDK context. This replaces
  a bare Pending future and stored waker that failed to sustain the IC call.
  The fixture requires at least one observed reply before checking interleaving
  and exposes call/decode errors in its failure state.
- Provider churn fixtures repeatedly replace 32,768 distant deadlines, cancel
  the last owned handle, then run 64 immediate Watchdog work units and advance
  beyond the cancelled deadlines. They assert functional behavior and report
  Wasm page extents. They do not establish a provider memory cap or cost bound.
- Structural release readers count fields independently of their expected value.
  Correct-plus-conflicting markers cannot pass. Note headings/statuses and the
  current dated changelog section are unique. Prose remains advisory.
- The commit hook checks an index snapshot without modifying working files or
  the index. It permits partial staging when the staged snapshot is formatted,
  and rejects unformatted staged content even if its working copy is formatted.
- `release-commit` can finish tagging an already committed matching release or
  verify its existing annotated tag. It never resumes from an arbitrary clean
  commit, replaces a tag or commits additional changes to a tagged version.
  `release-patch`, `release-minor`, `release-major` and `release-x` still always
  perform the requested bump. Recovery of their final phases is documented.
- The 0.8.4 note and handoff now distinguish the published baseline from these
  prepared changes instead of retaining obsolete preparation instructions.

## Preparation record and delivery

The new native, PocketIC and shell fixtures are written and wired into the
existing deployment gate. They were unexecuted at preparation on 2026-10-03;
the automated contributor ran formatting and a diff whitespace check only.
The maintainer subsequently reported ten PocketIC subjects passing and the
ordinary-await subject failing to observe suspension. The gate correction above
awaits a maintainer rerun; the earlier result does not qualify the corrected gate.
No new recovery, performance or measured memory result is claimed. Test, build
and lint execution belongs to the maintainer, as do staging, version bumps,
commits, tags, pushes and publication. The full CI, MSRV, nested-probe lint,
pinned PocketIC recovery and cohort gates remain required.

The maintainer has since created release commit
`9afb9a1be93c159400c1ff3cb63515f73d2a1d7e` and annotated `v0.9.0`. The dated
changelog, Cargo version and both lockfiles now select 0.9.0; the existing local
`origin/main` ref points to that commit. Publication and final successful gate
output were not verified by the follow-up review. These release artifacts do
not qualify unrecorded test results. The hard cut correctly uses the minor
compatibility boundary; its bump is complete.
